# 0.9.11 原生诊断材料与整态审计适配

## 实际失败与对照边界

0.9.10 的真实首轮被独立核验拒绝：医生把尚未领取的物品写入背包，并把已经生效的派生加成说成遗漏。当前状态确实完整传入，并非缺少快照。人物出现过度丧失自身目标的补全，World 只复述玩家背景；这两项尚未由本修复解决，不能报告十二回合通过。

在同一宿主、同一真实模型与冻结材料上，只读对照未应用任何返回：

- 原版自动请求两次没有错误赠送物品，但对已经错误入库的状态仍返回空补丁。
- 原版整态审计配合全量叙事世界书仍误判；不能据单次空补丁宣布修复成功。
- 使用原生 MVU 规则提取，并请求原版支持的整态审计，分别检查写错前与写错后快照：不再伪报派生加成；后者识别尚未领取的物品并提出移除。两者还提出了同一时间字段修正，其完整规则适用性仍需真实回合继续核验。

以上是故障定位，不是当前候选功能验收。私人材料、模型返回和连接信息不进入仓库。

## 来源映射（修改前记录）

| 部分 | 成熟来源 | 本次处理 |
|---|---|---|
| 诊断系统提示、当前状态、更新区块、对话、卡片与输出约定 | 固定 Story Oracle 1.35.4 `buildDiagnosePromptFrom`、`DIAGNOSE_SYSTEM_PROMPT` | 原样调用；删除 Doctor 重复追加的前后态五栏和附则 |

| 整态审计 | 同版 `DIAGNOSE_SYSTEM_PROMPT` 的“审计整个状态，而不只是最新一次更新”分支 | 将该原生任务范围放入一句 user 请求；不另建分析器或验证模型 |
| 无内联更新的推导 | 同版 `runAutoDiagnose` 的乙分支 | 保留原句请求与原生 auto 模式 |

| 固定楼层、证据并发、收据与读回 | 当前 Doctor 宿主适配 | 不变；前态仍用于事务有效性核对，不再重复灌入模型提示 |
