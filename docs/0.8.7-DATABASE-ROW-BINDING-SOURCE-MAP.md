# 0.8.7 数据库来源行绑定与失败证据来源映射

## 本轮真实失败

- 当前源码 `a4852adb8251a653264a46dd9218f34751f2846a` 的真实 TauriTavern 验收中，第一回合在约 85.6 秒内完成 MVU、1 张完整人物档案、世界推进与注入消费。
- 第二回合的人物模型返回了内容档案，但把正文稳定称谓改写成了创造性姓名。旧链在校验前按 `name/aliases` 过滤，先删除整张档案；唯一一次修复仍让模型重复证明同一身份，最终错误地报告“候选没有对应档案”。
- 同一次失败的初答和修复答已经收到，但公开报告字段只在整批成功后赋值，因此失败报告中的人物提示与模型原文为空。

## 成熟来源

### 数据库来源行拥有身份

- 来源：用户提供的 `数据库模板-super自定义7.12总版-caikis.json`，SHA-256 `219e60b9327d8cf28e18abc3eabe675996ccf4f03f872a2a8ce424f6a7179742`。
- `NPC表/first_npc` 以 `name TEXT NOT NULL UNIQUE` 保存稳定称谓；`追踪角色表/second_npc` 从来源行 `SELECT name`，AI只填写别名、年龄、属性等缺失内容。未有权威真名前继续保留专属称谓；以后确认真名时才把旧称谓移入别名。
- 当前落点：`profileTargetRows` 把本批候选变成脚本持有的 `{rowId, sourceName}`；`bindProfilesToTargetRows` 在完整性校验前按 `rowId` 绑定，强制保留 `sourceName`，把模型创造性姓名保存为可修订别名，并在提交前删除技术字段 `rowId`。
- 复用等级：身份所有权和逐来源行填表边界直接复用；SQL `INSERT ... SELECT` 不能放进人物 JSON 输出，因此只把语法最小适配为稳定 `rowId`。这不是新状态机。

### Life State ver5.35 先保留请求再校验

- 来源：冻结原件 `vendor/life-state-v5.35/`，SHA-256 由 `PROVENANCE.json` 与验证脚本固定。
- 原件由脚本持有 `restore_request/name`，修复请求继续携带原请求、失败候选和精确错误；候选先按请求对象归一化，再验证，失败候选不会在修复前丢失。每次外接模型响应到达时立即写入 trace。
- 当前落点：人物初答与唯一一次修复都走同一顺序：`parse/normalize → bind targetRows → 现有范围过滤 → validate`；提示、初答和修复答每次到达后立即同步到报告字段。
- 复用等级：处理顺序和即时 trace 模式直接复用；人物字段结构仍是 Doctor 现有结构，不冒充完整 Life State 运行时。

## 最小适配

- 单目标且只返回一张档案时，即使旧模型漏回 `rowId`，请求目标仍唯一，可以像 ver5.35 的单一恢复请求一样绑定；不再为兼容旧模型额外调用一次修复。
- 多目标必须逐张原样返回 `P1/P2…`。缺失、重复或未知行键只进入既有的唯一一次修复；仍错误则整批失败，不按数组顺序或姓名相似度猜配。
- 本轮其他目标的稳定称谓不能被前一批或后一批作为别名吞掉；批次汇总只按来源主名替换，不再因任意别名重叠而覆盖另一张档案。所有批次仍只做一次原子提交，失败不留下半张档案。
- 已有档案若由正文别名命中，目标行同时携带已有 canonical name；手动补档保留既有主名并把当楼称谓留在 aliases，不反向改名。
- 人物填表不再要求模型同时维护 `detectedCharacters` 平行身份名单；绑定后由脚本从档案主键派生，人物发现阶段自己的小名单保持不变。
- 重 roll、取消或切换聊天若发生在模型响应到达之后，`cancelled/stale` 结果也携带已经收集的提示与原始响应；任务失权仍阻止提交，但不再抹掉取证。

## 明确删除

- 删除旧的 `dropProfilesOutsideBatch` 姓名反向过滤链。它会在脚本还没有绑定请求目标时删除模型候选，是本次真实失败的直接原因。
- 没有增加第二次修复、模糊身份匹配、人物状态机、额外任务门或新的持久化结构。
- 没有修改 Story Oracle、World Engine 或 Life State 三套冻结原件；数据库、MVU、Doctor 档案、预设与世界引擎继续各自拥有自己的状态。

## 回归合同

- 单一稳定称谓可以绑定一张创造性补全档案；稳定称谓是当前主键，创造姓名进入别名，`rowId` 不得持久化。
- 两个目标即使乱序返回，也只按 `rowId` 绑定到各自来源行。
- 前批别名不能吞后批，后批别名也不能覆盖已完成前批；最终人物数必须与目标行数一致。
- 多目标缺行键、重复行键或未知行键只能使用既有一次修复；失败时零档案提交、零世界推进。
- 失败结果、持久运行报告与导出报告都必须保留非空的初答、修复答、初始提示和修复提示，同时继续排除 API 配置与凭据。
