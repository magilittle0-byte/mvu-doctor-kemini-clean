# 0.9.4 World 行动主体接缝来源映射

## 真实失败与根因

0.9.3 的首轮真实酒馆复核中，变量诊断、人物档案原子提交和 World 原生 API/持久化都完成，但 World 返回的公开事件、势力、趋势、风声、仇敌与影响链均为空，只在 `blackbox` 保存了既有背景行为。该轮已判失败，不能作为可用证据。

取证确认不是适配层丢弃模型结果：原生 World 收到并成功解析的返回本身就是空世界字段。0.9.3 只等待变量诊断，人物填表与 World 并行；World 首轮开始时既没有既有事件/势力，也没有 Doctor 刚生成的人物档案。World 3.0.2 允许这种合法的 `blackbox-only` 返回，所以“调用成功”并不等于“产生了自主世界行动”。

## 发送给 World 的边界

行动主体投影只包含完整非玩家档案的身份摘要、全部性格行动轴、当前位置/状态/目标、关系、知识、能力和资源，并限制为最多 12 人、16,000 字符、每列表 4 项、单字段 180 字符。当前世界、本轮用户输入或最终正文直接相关人物最多占 4 个优先位置，其余位置按 World 当前轮次在稳定人物列表中轮换；存在后台主体时至少为其中一人保留实际字符预算，避免人物多时永远只选玩家身边的最近档案。关闭 Doctor 总开关或“完整人物档案填表”开关后，既有档案也不再发给 World；原生 Memory 的独立开关只管理 Memory 自己的内容，不被 Doctor 改写。以下内容明确不发送：

- 宿主当前用户名、聊天锁定 persona 及同聊天历史用户消息署名命中的玩家档案；身份只取宿主权威字段，不从正文猜测姓名，也不把未锁定的默认 persona 当作当前玩家；
- 原始 MVU 与数据库表；
- `history`、`evidence`、`inferences` 等长历史/证据链；
- Doctor 任务、诊断、报告和内部票据。

附加合同只要求 World 每轮从现有人物、势力或环境/社会过程选择至少一个非玩家主体，根据自身目标与有限条件形成具体尝试、准备、观察或计划变化。人物阶段启用但暂时没有完整人物投影时，这一段仍保留，只允许从当前世界状态、已选世界书和近期对话中既有的势力、环境或社会过程推进；关闭 Doctor 或人物阶段时则完全不追加。冻结 World 会把模型本轮 `blackbox` 整批替换到状态，因此同一段明确要求仍有效的秘密行动/资产即使本轮未变也继续返回，只在完成、曝光、失效或有事实更新时改变；这是提示约束，不是第二套解析或门禁。它同时保留 World 原生规则：行动需裁决，私密内容进 `blackbox`，只有合法观察/传播的后果才能公开，且不得替玩家行动、发言、感受或同意。

## 没有新增的东西

- 没有第二个 scheduler、世界状态机或世界存储；
- 没有修改 World JSON Schema、解析器、重试条件或成功门禁；
- 没有把随机事件概率改成 100%；
- 没有把人物档案写入 World 持久状态；
- 没有恢复 0.8.x 的全量 MVU/人物 dump；
- 没有用“必须产生事件”的后置审查阻塞原生 World。

## 验证边界

静态、Node 和无头浏览器回归只证明接缝没有破坏原生所有权、人物投影有界且同楼等待语义正确，不能证明实际世界质量。`tests/vendor-world-actor-seed-chain-browser.cjs` 使用合成资料和唯一的模型运输 stub，真实加载冻结的 World/Memory，实现行动主体从 Memory 上下文槽进入原生最终提示、宽容解析、合并、IndexedDB 保存/重载读回，以及 blackbox 对正文/Memory 的公开投影隔离；它仍不是实际模型或酒馆验收。0.9.4 必须与上述本地预设在同一个全新真实聊天中连续完成十二个有效回合，并逐轮人工核对变量、档案、世界行动、防全知和玩家自主权，才能声称可用。
