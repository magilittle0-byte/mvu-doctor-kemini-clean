# 0.8.9 人物发现称谓绑定来源映射

## 真实失败

功能试跑第 2 回合中，人物发现模型返回了一个正文没有逐字出现、也不属于已有档案的名字。原流程先将其静默过滤，随后因“检测到人物但没有可提交档案”直接失败；变量修复已成功，但人物没有提交，世界因此没有推进。旧档案保持完整，没有留下半张档案。

## 成熟来源与复用等级

| 来源 | 成熟机制 | 本版处理 |
| --- | --- | --- |
| `vendor/life-state-v5.35/life-state-v5.35.js` 的 `buildRepairMessages`、`repairTurn` 与校验失败分支 | 将原候选、`validation_errors` 和原请求材料交回同一模型，最多执行一次定向修复；修复后重新走同一校验 | 直接复用调用顺序和失败语义，最小适配到人物发现结果 |
| 0.8.7 数据库来源行绑定 | 脚本持有 `rowId/sourceName`，模型只填内容；无法绑定时不猜测、不按顺序错配 | 原样保留。修复后的发现称谓仍必须先成为脚本来源行，才允许完整填表 |
| 0.8.8 人物完整度与原子提交 | 全字段校验通过后一次提交；失败不留半张档案、不推进世界 | 原样保留 |

## 最小适配

- 初次人物发现仍只调用原有发现提示词。
- 新增的校验只确认每个返回称谓是否逐字出现在最终正文，或原样命中脚本已从本楼结构提取的人物线索。
- 校验失败复用现有 `discoveryRepairPrompt` 和原有一次修复槽位，不新增队列、状态机、持久字段或独立模型路由。
- 修复提示收到原候选、校验错误、最终正文和结构人物线索；它只能把称谓改为可绑定的正文称谓，不能从世界书偷偷换成正文未出现的真名。
- 初次候选已经报告有人物但称谓无法绑定时，这一人物存在义务会延续到单次修复；修复必须保留初次已经正确绑定的称谓，且不同人物数不得少于初次报告数，不能通过清空或部分删人改口称“本轮无人”。
- 第二次仍无法绑定时继续失败关闭，人物档案不提交，世界不推进。

## 没有采用的做法

- 不接受正文外真名，避免世界书人物或模型偏好被误当成本轮实际出场人物。
- 不恢复模糊匹配、数组顺序绑定或名字相似度猜测。
- 不把无法绑定人物静默当成“本轮无人”，避免漏档案被伪装成成功。
