# 0.6.16 accepted content 边界来源映射

## 真实故障链

0.6.15 当前源码与精确配对预设在真实 TauriTavern 全新聊天首回合产生一份 accepted-final。独立取证确认字面拓扑为：

`<content> → 正文/检定/UI → <options> → <UpdateVariable> → </content>`

`repairAcceptedNarrativeEnvelope` 用当前真实 `core.mjs` 独立复演，与 Doctor 运行诊断一致返回 `accepted-structure` 失败。变量、人物和世界阶段均未开始，档案数与世界修订保持零。这排除了“面板没刷新”或“Doctor自报错误”的假设，根因是预设物理标签合同仍含歧义，同时 Doctor 缺少对这一种可完全证明的轻微错位做本地修复。

## 成熟来源与采用方式

| 来源 | 完整核对的机制 | 采用方式 |

| Z论坛 | 本轮全项目文件名与相关关键词检索无可用实现 | 无可复用实现 |

## 必须新写的窄边界

成熟来源没有“唯一content闭合被放在完整options与UpdateVariable之后”的同构修复函数。因此 0.6.16 只新增一个窄分支：

1. content 开闭标签各一个，且正文非空；
2. 闭合标签之后只能有空白；
3. content 内尾部只能由完整的 `options`、`UpdateVariable` 块组成；
4. 每种块至多一个，开闭计数与完整块数一致；
5. 块之间以及最后一个块与错误闭合之间只能有空白。

全部成立时移动已有 `</content>` 到首个结构块之前；任一条件不成立时继续返回原结构错误。修复不生成新正文、不改选项、不改JSONPatch，也不降低下游变量、档案、世界或读回标准。

## 所有权与验收边界

- 预设负责生成阶段的字面拓扑与正文；Doctor只在 accepted-final 后修复可证明的结构错位。
- MVU继续维护实时变量；数据库独立填表；Doctor人物与私有世界不接管数据库。
- 任何 0.6.16 运行代码或配对预设变化都会使 0.6.15 真实证据失效；自动测试与测试仓推送不是正式可用证据。
