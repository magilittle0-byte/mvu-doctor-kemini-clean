## 使用与调用次数

| 模块 | 正常每轮请求上限 | 当前功能 |
|---|---:|---|
| MVU 变量修复 | 1 | 根据正文和变量规则检查，经官方 MVU 执行并独立读回 |
| 人物档案 | 2 | 自行发现人物，批量设计并填写完整 44 字段档案，无需预设输出专用档案标签 |
| 世界引擎 | 1 | 保存、推进世界与离场人物，将公开后果交给下一轮正文 |

正常医生流程最多 **4 次调用，自动重试 0 次**。内容有误时使用相应模块的修复按钮。一次变量修复最多额外 4 次（含档案与世界联动）；一次档案修复最多额外 3 次；一次世界修复额外 1 次。修复按钮会再次生成，不保证模型一次就纠正全部内容。

当前电脑无需重复安装。其他环境通过本测试仓安装变量扩展，再导入并启用 [人物档案脚本](../profiles/install.json) 和 [世界引擎脚本](../world/install.json)。同一模块只启用一份。当前入口和版本以 [三个模块的锁定清单](../locks/phase3.json) 为准；保留已验证的运行文件和安装文件原字节。

## 真实核验结果与限制

- **变量**：13 轮均独立核对正文、修改前后值和存档。实际变量修复按钮在第 2、6、11 轮使用；有成功修复，也有第 11 轮重新生成后仍未纠正的生命值错误。装备数值、体力、位置范围和额外时间推进等模型误判没有改写为成功。
- **人物档案**：最终保存 **13 份完整档案，每份 44 字段**，详情、索引表与存储读回一致。第 6、9、10 轮实际使用档案修复按钮；不完整或错误 ID 的候选未作为完整档案保存。第 9、11、12 轮的部分任务失败仍保留，不因最后一轮完成而追认恢复。旧集体档案残留和最后一轮带队者的身份连续性不确定，也列入模型例外。
- **世界与召回**：世界持续推进到第 13 轮，私密状态与离场活动保存；第 3 轮实际使用独立世界修复按钮，同一轮重新计算没有冒进新世界轮次。第 9 轮独立观察到一个上一轮公开冲突后果在正文出现，补足此前只有注入证据、没有实际正文采用证据的问题。这个结论只覆盖该后果，不扩大为全部召回都已采用；机器的保守 `semanticConsumptionProven=false` 原样保留。
- **知识边界**：本批正文未观察到私密黑箱泄露；公开世界描述仍有模型写入未被目击因果的风险。最后一轮公开命令、带队者和搜查已成为可观察事实，但没有证明带队者与既有档案是同一人。没有把“未观察到泄露”写成绝对防泄露保证，也没有用后来的公开喊话追认早先不确定的归因。
- **恢复与前端**：唯一一次刷新后，原聊天、13 轮历史、MVU、档案和世界记录保持一致，三个模块恢复，新增模型调用 **0**。世界面板 21 项实际结构值全部匹配。严格文本 hash 仅世界 UI 不同，原因是存储恢复改变 JSON 键的显示顺序；原失败诊断保留，没有伪造严格通过。界面值已刷新、发送入口可用，未观察到医生阻塞正文。后台 1280×1292 截图未出现底部白带，但宿主最小化，前台原生窗口显示不在本批证据范围。

最后一轮耗时：正文 **67.633 秒**、变量 **26.295 秒**、档案 **87.174 秒**、世界 **44.723 秒**。这些是各阶段记录，不应相加当作端到端耗时。
