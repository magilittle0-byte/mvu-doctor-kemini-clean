# 0.9.1 变量闭环取证来源映射

## 真实失败

0.9.0 的真实酒馆首回合出现了可复现的语义漏判：本轮输入和正文给出了明确初始值与奖励后的目标值，原更新却把奖励增量应用在旧默认值上。最终 MVU 仍是旧默认值加奖励；Story Oracle 返回了一个对当前状态无作用的补丁，Doctor 因而记录为 `nochange`。

这不是 JSON 提取、官方 MVU 解析或持久化错误。0.9.0 只显式传入本楼 post-update 状态和原更新块；触发输入与最终正文埋在受正则和深度影响的 transcript 中，且没有上一有效 MVU 前态。原件提示又强调“更新效果已在当前状态中就视为成功”，所以无法稳定识别“正确增量应用在错误基数上”。

## 原样保留

- Story Oracle 1.35.4：世界书与 MVU 规则收集、`buildDiagnosePromptFrom`、连接调用、`extractUpdateBlock`、通知与消息刷新。
- 官方 MVU：`parseMessage`、`replaceMvuData`、固定消息楼层写入与读回。
- 0.9.0 Doctor：聊天/楼层/swipe 所有权、调用期间 post-state 摘要不变检查、失败回滚与持久报告。

## 最小移植

| 机制 | 成熟来源 | 0.9.1 适配 |
|---|---|---|
| 本轮证据分栏 | `legacy/0.7.5/index.js` 的 `buildVariableAuditEvidence` 与单次变量审计提示 | 在 Story Oracle 最终 user message 末尾按 `pre → post → 原块 → 触发输入 → 最终正文` 放置闭环材料 |
| 上一有效 MVU | 正式医生 `previousMvuData` | 从当前目标向前扫描最近一个非用户、非系统且含可用 `stat_data` 的楼层；缺失时降级，不阻断本轮 |
| 最终正文去机制块 | Story Oracle `stripMechanismBlocks` | 直接调用原件函数，保证有原更新块时正文仍作为独立证据出现 |
| 修复语义 | 旧 Clean 0.7.5 的 post-state 残差补丁约束 | 原更新与当前值只是待核对对象；先独立推导应有变化，再比较 pre/post；补丁只叠加当前 post-state，不重放原 delta |
| 空补丁展示 | 旧 Clean 0.7.5 的 `model_reported_nochange / semanticProof:false` | 保留兼容状态 `nochange`，增加 `semanticProof:false` 和诚实中文结论，不把模型空补丁描述成脚本证明正确 |

## 明确未移植

- 没有加入第二模型、额外语义门禁或新的状态机。
- 没有移植旧 Doctor 的自建 JSON 解析、WAL、全量 diff 和大合同。
- 没有启用官方 MVU extra-model，避免两个变量写入者竞争。
- 没有移植数据库 SQL/CRUD、Izumi 格式块或缝合怪的上下文排除逻辑。
- 没有修改 World Engine 原生调度、状态、重 roll、注入、持久化或 UI。

## 验证边界

浏览器回归使用合成数据验证证据包顺序、最终正文独立存在、前态缺失可降级，以及纠正补丁针对 post-state 写入而不重放原 delta。它只证明组装和事务链，不证明真实目标模型必然理解语义；后者必须重新从全新真实聊天开始验收。
