# 0.8.1 正文接管生命周期来源映射

## 已删除的自建机制

0.8.0 后续补丁曾用 `generationEventStack` 把每次 `GENERATION_STARTED` 与 `GENERATION_ENDED` 按 LIFO 配对。真实 SillyTavern 会让 dry-run 发送 START 后直接返回且不发送 END；数据库和扩展生成与正文生成也不保证严格嵌套。因此一个后台 START 会吞掉正文唯一的 END，使 Doctor 永久停在“正文生成中”。0.8.1 完整删除这套栈及其裁决逻辑。

## 直接复用的成熟机制

- 来源：`vendor/story-oracle-v1.35.4/index.js` 的 `MESSAGE_RECEIVED(id)` 监听与同步 fire-and-forget 外壳。
- 复用内容：用宿主提供的 numeric message id 固定已落盘 AI 楼层；事件监听器不返回长 Promise，避免 SillyTavern 等待扩展任务而堵住后续 END。
- 适配程度：事件入口和固定楼层语义直接移植；函数名及 Doctor 票据字段按本项目命名。

## 最小宿主适配

- 来源：真实 SillyTavern `script.js` 的两种时序：非流式为 `MESSAGE_RECEIVED → GENERATION_ENDED`，流式为 `GENERATION_ENDED → MESSAGE_RECEIVED`。
- 适配内容：在同一生成票据上分别锁存 `receivedMessageId + receivedSwipeId` 与 `endObserved`，两者任意顺序到齐后只调度一次；随后继续使用既有的 650ms 两次固定楼层/固定 swipe 新鲜读取。`regenerate` 的最终 swipe 不在开始时猜测，只在真实 `MESSAGE_RECEIVED` 到达时绑定。
- 原因：`GENERATION_ENDED` 是全局 UI 事件，不能给出可靠楼层；`MESSAGE_RECEIVED` 能给楼层，但单独使用又不能证明主生成生命周期已经结束。两者汇合是宿主时序所需的最小胶水。

- 来源：真实 SillyTavern `script.js` 的 `MESSAGE_SWIPED(message_id)` 时序；宿主先切换 `swipe_id/mes` 并发出事件，再启动 overswipe 的 `Generate('swipe')`。
- 适配内容：活动票据期间任何 swipe 变化都作废旧票据；随后真正的 `GENERATION_STARTED('swipe')` 从新槽建立新票据。监听当刻从固定 message id 读取 swipe id，不接受自造的对象参数。

## 新写部分及原因

- `receiptTargetForTicket`：只允许活动票据对应的 AI 楼层和已绑定 swipe；普通回合必须位于基线之后，reroll/continue 必须仍是原楼层。
- `scheduleAcceptedGenerationIfReady`：双信号原子汇合与 `completionScheduled` 幂等保护。
- `awaitingStart` 防串线：`MESSAGE_SENT` 建立的暂定票据在看到匹配 START 前忽略无身份的迟到 END 和收据。
- 刷新归并：完整票据按固定楼层/swipe恢复；received-only 在刷新终止边界闭合；END-only 只有能严格重建同一目标时才闭合；纯 START、目标消失或 swipe 漂移直接清票。
- 无用户楼、无落盘收据的后台生成清理：在 END 到达时冻结是否已有用户楼，后来出现的用户输入不能追认旧后台任务；主回复的合法迟到收据不使用武断总超时，新用户回合到来时才中断仍无收据的旧票据。

这些代码是宿主胶水，成熟作品中没有可直接复制的 Doctor 三阶段票据实现；没有新增并行编排器、额外模型门禁或另一套状态机。
