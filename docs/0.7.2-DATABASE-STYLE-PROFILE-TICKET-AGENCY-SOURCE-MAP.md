# 0.7.2 人物档案补全、票据消费与玩家自主权来源映射

本版本不是在旧门禁上继续堆规则，而是把人物档案流程收束为成熟作品已经验证过的三段式：生成前确定人物创作来源，生成后由模型完成整张档案，脚本只做宽容解析、冲突隔离和原子提交。

| 成熟来源 | 已验证机制 | 本版本采用方式 | 适配边界 |
| --- | --- | --- | --- |
| 数据库本体的重要人物表与表格模板 | 新人物首次插入时一次填成完整行；正文提供硬事实，模型补足未明说字段 | 最小适配到 `repairProfileReceipt`：正文与权威材料只锁定不能冲突的事实；外貌、习惯、经历、表达、欲望、弱点等由人物模型主动补全，并进入可修订推断 | 数据库仍独立填自己的表；Doctor只写自己的人物档案根，不接管数据库表格 |
| 数据库补丁层 | 模型输出采用短合同；围栏、标点、缺逗号、轻微字段偏差由本地修复，不因小格式问题整批重跑 | 继续复用现有宽容回执解析和字段归一化；越权知识局部下沉为推断，保留其余完整字段 | 不降低完整档案标准；只有整张档案可解析、可用并能原子读回时才提交 |
| NPC Tracker 人物档案生成 | AI基于世界与上下文推断完整人物；单个人物失败不应让其他后台流程整体停摆 | 人物内容/格式失败记录可重试，但不再阻断已有世界主体和非人物主体推进 | 人物档案写入、读回或身份事务未闭合仍会阻断世界，防止消费半提交状态 |
| 旧 Doctor 人物假设与骰票 | 创作信息作为可修订假设保存；同一人物沿用生成前骰票 | 重新实现 `CharacterTicketReceipt`：预设在正文生成时优先记录每个实际出场人物来自 ticket、authority 或 existing；有效映射只绑定已消费的同一张票 | 回执是优先谱系而不是建档门禁；漏写、损坏或漏人时完整无票建档并标记来源，绝不在正文后从剩余票据池任配 |
| 故事神谕变量修复 | 单一聚焦提示词判断，写入使用宿主/MVU官方重放与刷新链路 | 变量提示新增玩家显式姓名、身份、点数、资源优先级与玩家自主权；明确标记的只读路径在官方重放前被剔除，重放结果相同的冗余派生操作也由脚本删除 | 不增加新的自由文本语义状态机；只识别同一行明确标记，或嵌套 Schema 中经纯容器键连接到标记项的最近低缩进路径标题；遇普通正文或同级结构立即停止 |
| Izumi 0825 与糖糖公司 A 锁 | 正文生成过程内约束玩家边界；原创人物在生成前取得多轴创作来源 | 只在本地私有预设的原有两个用户条目中追加 A 锁与票据消费回执，247 个提示条目和 214 个顺序项保持不变 | 私有预设不进入公开仓库；Doctor 仓库只提供通用回执协议与兼容逻辑 |

## 本版本必须新写的宿主适配

- `CharacterTicketReceipt` 的宽容解析、聊天/楼层/swipe/正文指纹谱系保存，以及重试时的精确继承。现有参考没有 Kemini Clean 当前宿主生命周期的同接口实现；其缺失或损坏只形成诊断和无票来源标记，不否决已经完整的人物档案。
- 官方 MVU 重放后删除“移除该操作仍得到完全相同最终状态”的冗余操作。它只依据官方重放等价性，不猜测角色卡 Schema。
- 人物内容失败与人物持久化失败的分流：前者不冻结世界，后者仍失败关闭。现有参考的状态所有权与本项目不同，不能原样搬用。
- 跨回合人物补档复用现有人物根事务与swipe快照：原楼层正文/票据仅作为不可变证据，当前最新MVU是唯一写入目标；成功时同步继承分支并只清对应旧任务，绝不倒序重放变量或世界。
- 完整报告导出与日常诊断脱敏分流：导出只排除真实 API 容器、授权凭据及当前连接值，剧情和变量中的同名业务字段逐字保留。现有参考没有本扩展运行快照的同接口实现，因此这部分是必要的宿主适配。

## 明确未做的事

- 没有让 Doctor 接管数据库表格、预设创作或世界书设定。
- 没有从正文后重新掷骰或替新人物挑剩余票据；缺失映射的人物会明确保存为完整无票档案，而不是伪造一个票据归属。
- 没有把普通自由文本交给脚本正则做人物语义裁决。
- 没有把模拟测试或源码测试当作真实酒馆验收。
