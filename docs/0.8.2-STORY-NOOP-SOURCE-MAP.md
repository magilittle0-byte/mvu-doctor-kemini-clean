# 0.8.2 Story Oracle no-op 语义来源映射

## 真实失败

0.8.1 的首轮真实酒馆检查中，正文原有的 MVU 更新已经成功改变固定楼层状态。Story Oracle 随后返回一条语法有效的 `replace` 修正，但该路径当前值已经等于修正值；`Mvu.parseMessage` 因此返回与固定楼层完整 payload 等值的结果。0.8.1 把这种合法幂等结果升级成 `story_oracle_nonempty_noop` 硬失败，人物档案与世界引擎随之都未执行。

## 直接复用的成熟语义

来源：`vendor/story-oracle-v1.35.4/index.js` 的 `autoApplyFix`。

- `parseMessage` 无法返回数据：`failed`；
- `newData` 与 `oldData` 完全相同：`nochange`；
- 只有二者不同：`replaceMvuData` 并返回 `applied`。

0.8.2 将非空幂等补丁恢复为同一 `nochange` 分支，不写变量、不改正文，并继续人物档案和世界推进。

## 最小宿主适配

以下既有适配保持不变：固定 `{messageId, swipeId}`；模型调用前后验证固定楼层基线未漂移；实际写入后按固定楼层读回；无可识别 `UpdateVariable` 的模型返回仍归解析失败。最后一项不是 no-op：它没有可供 MVU 解析的候选，不能与“候选解析成功但结果等值”混为一类。
