# 0.6.20 来源映射：世界裁决语义终态

## 真实失败链

0.6.19 的真实 TauriTavern 同一聊天第2回合中，正文 accepted-final、真实 MVU 重放、完整人物档案原子读回、公开召回锚点消费和前端刷新都通过。世界模型返回一个已绑定建档人物的行动尝试与 `status=success` 裁决；裁决有私有结果摘要、实际耗时和未来发现路径，但 `appliedStateChanges=[]`。旧 `validateWorldProposal()` 只要求 `resultSummary / observableConsequence / consequence` 三者之一，`applyWorldProposal()` 又只要结果摘要非空就把 attempt 标成 `settled`，于是“成功但世界没有任何实际变化”被持久化并显示为成功。

真实链路为：

`世界模型返回 -> parseWorldProposal -> 唯一关联修复 -> 公开投影清理 -> validateWorldProposal误放行 -> applyWorldProposal以摘要结算 -> 两阶段提交与读回成功 -> UI显示success`

这不是解析失败、前端漏刷新或报告误报，而是提交前语义终态合同缺失。

## 搜索后未复用的范围

- 糖糖公司与 Izumi 继续负责正文生成前的人物/视角/玩家边界，不拥有 Doctor 世界裁决提交权，因此不把它们的创作提示搬进世界验证器。
- 缝合怪负责提示整合与规划，规划不能成为已发生世界结果，因此没有复用其计划字段作为 `appliedStateChanges`。
- Z论坛只提供事件/舆情材料，不提供权威世界成功终态。
- 故事神域在当前项目文件清单中没有可定位的新实现；可定位的 Story Oracle 已完整核对其 waypoint/证据后推进纯函数，但没有复制其弧线状态机。
- 数据库本体与表格模板继续独立写自己的表；本轮只沿用其“结构本地修、语义缺项才重试”的边界，没有复制SQL、表格或数据库状态。

## 实际修改

1. `validateWorldProposal()` 现在要求人物行动有预计耗时和风险，裁决有有效状态、私有结果摘要与实际耗时。
2. `success/partial` 必须至少有一条完整 `appliedStateChanges`。公开行动还必须有安全可观察后果；隐秘行动没有公开表象时必须有未来发现路径。
3. `applyWorldProposal()` 在提交层重复守住同一最小终态：即使上层调用错误地绕过 validator，坏裁决也只能留下 `pending_world`，不能进入 adjudications 或把 attempt 标成 settled。
4. 世界提示词把这些要求写成字段含义与结果边界，没有增加嵌套JSON、第二次审查员或额外模型阶段。
5. 配对的本地 Izumi 0825 预设没有改动；数据库、MVU、Doctor 私有世界、缝合怪和预设的所有权不变。

## 非验收验证边界

本版本的单元测试、语法检查、JSON解析、运行时嵌入核对与凭据/私人文件扫描只证明候选可安装且特定回归被封住。因为运行代码和提示词均已变化，0.6.19 的真实回合证据全部失效；0.6.20 必须更新真实扩展后，从另一个全新聊天重新执行十二回合唯一验收协议。
