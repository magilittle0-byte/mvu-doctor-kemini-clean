# 0.9.3 成熟 World 适配根修来源映射

## 结论

0.9.3 不重写世界引擎。`vendor/world-engine-v3.0.2/` 继续固定 DlSNlGHT/World 提交 `154de4b590378cd0bd851cfffcefd3d96741cf3f`，45 个上游文件由 `npm run verify:vendor` 做逐字节校验。本次只修复快照外 Doctor 适配层对原生行为造成的三处干扰。

## 来源与采用方式

| 问题 | 成熟来源 | 采用方式 | 本地落点 |

## 保留的防全知边界

Doctor 只修改交给正文与 Memory 的深拷贝。完整 World 状态、checkpoint、下一轮推演输入和原版 UI 不受影响。投影继续隐藏后台 `worldDigest`、势力私密目标/核心人物/权力支柱、敌人、影响链和黑盒；事件/风声仅把“公开等级判断”交还原版 World，风声保留主题和来源。用户启用原版“全部等级”时，适配层尊重该原生设置。

## 为什么没有规定 World-first 或 Profile-first

原版 World 在宿主事件后自行等待 1500ms，并独立判断 auto/time/manual。若 Doctor 复制这套判定或新增一个世界调度器来强制业务顺序，就会重新制造 0.8.x 已删除的双重所有权。0.9.3 只保证共享网络请求不并发；人物、World 与 Memory 仍分别拥有自己的任务、重试、取消、回滚和持久化结果。

## 配对本地预设

用户的预设不进入仓库。与本候选配对的本地文件为 `01_主预设_人物万花筒_IZUMI0825完整保留_MVU适配_0.9.3成熟边界候选版.json`，SHA-256 为 `242c1c301f715b91a6e2fa6e9d8aec70696e3b8a0dedd245a36864c60e887fb5`。它从用户指定的完整保留版 `cdd7204c...34c8` 生成，提示对象数量、顺序、启用状态、正则、脚本和生成参数均不变；只在现有三个适配提示中恢复 IZUMI 0713/旧 0.6.15 已有的玩家控制边界，并把重复的 `currentAction` 禁令压缩为一次映射。

## 非验收性回归

- API 通道：并发最大值 1、五参数透传、首次失败和排队前取消均会放行下一项、重复安装不重复包装；
- 原生手动路径：forward、redo、手动时间推进在空 `aiMsg` 时均不等待不存在的诊断；
- 助手路径：诊断完成前不调用原生 evolve，机制块过滤后为空也不能冒充用户尾楼，旧 swipe 的 stale 只取消旧调用；
- 公开投影：Lv3 进行中事件与风声 `topic/source` 可见，Lv2 进行中事件按原生默认隐藏，全部等级开关生效，私密字段不进入正文或 Memory；
- 冻结原件：Story Oracle、World 与 Life State 三套来源校验仍必须通过。

这些回归只证明适配合同。0.9.3 仍须使用当前源码指纹和配对预设，在同一个全新真实聊天中连续完成十二个有效回合后，才可能声称可用或进入正式发布。
