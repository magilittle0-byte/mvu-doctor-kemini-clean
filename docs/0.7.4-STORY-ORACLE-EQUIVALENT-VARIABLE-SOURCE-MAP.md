# 0.7.4 Story Oracle 等价变量医生来源映射

## 范围与基线

- 成熟参考：Story Oracle `v1.35.4`，commit `661f9f89446de473ace70a590897ca5065bc2efe`。
- 参考实现：`story-oracle-upstream/index.js`。本地参考归档中的 `index.js`、`README.md`、`manifest.json`、`style.css` 与该快照逐字节一致。
- 本版目标：等价改写 Story Oracle 的变量诊断主链，而不是复制它的页面、连接系统或侧聊产品形态。
- 变量阶段只负责 MVU。人物档案、数据库填表、世界后台推进与正文生成仍由各自模块独立负责，不进入变量诊断提示词或应用判定。

用户本轮提供的跑团与 Doctor 报告仅作为本地故障证据读取。附件原文、文件名、路径、正文、变量快照、模型返回与 API 信息均未复制进仓库、测试夹具或本文，也未上传到任何外部服务。

## 等价主链

```text
回复后异步触发
  → 等 MVU 原更新先落地
  → 捕获并锁定本聊天 / 本消息 / 本 swipe
  → 收集规则、当前状态、本回合更新或正文、最近剧情
  → 一次变量诊断模型调用
  → 提取一个 <UpdateVariable>
  → 官方 Mvu.parseMessage
  → 无变化则结束；有变化则 Mvu.replaceMvuData
  → 必要时把更新块写回原消息并保存
  → 刷新消息与状态栏
  → 保存最小撤销 / 恢复记录
```

模型负责判断“哪里错、应怎样修”；脚本负责目标绑定、调用、提取、交给 MVU、保存、刷新和恢复。脚本不再自行重构整回合变量结果，也不再用一组并行语义门禁代替 MVU 官方解析器。

## Doctor 必须保留的最小宿主层

这些机制不是第二套变量医生，只负责让 Story Oracle 的简单语义链安全落在 Doctor 的异步、多 swipe 环境中。

### Identity

- 模型调用前捕获聊天身份、消息编号、swipe 编号和接受正文指纹。
- 模型返回后、状态写入前、消息写回前各核对目标仍相同。
- 目标已切换就保存为可重试的陈旧任务；绝不退回“最近一条 AI 回复”，也不写到新聊天或新 swipe。

### Readback

- `replaceMvuData` 后只做一次目标消息读回，确认官方解析结果确实持久化。
- 读回只验证本次准备写入的结果和非本任务所有权字段没有丢失；不再启动全状态语义审计。
- 状态栏是否刷新不等同于数据是否持久化，两种结果在诊断中分开显示。

### WAL 与撤销

- WAL 只记录：目标身份、应用前必要快照、本次更新块、应用结果、读回结果和是否已撤销。
- WAL 不保存一份由 Doctor 自己推演的“理想整回合状态”，也不驱动下一轮模型生成。
- 恢复 / 撤销只处理本事务实际改变的路径，并在恢复后读回；之后由其他系统写入的合法变化不被整盘覆盖。

### UI

- 用户首先看到五种普通结论：已修复、无需修改、输出不可解析、目标已变化、写入 / 刷新失败。
- 显示“模型说正确”不等于显示成功；只有官方解析与目标读回完成才显示已修复。
- 保留手动重新检查、定向重试和撤销；详细模型原文、补丁与宿主错误放在折叠诊断中。
- 自动变量任务始终在正文之后运行，不能让其忙碌态阻塞下一次正文生成或重 roll。

## 0.7.4 明确删除的旧完整替换机制

下列机制不属于 Story Oracle 的成熟变量主链，0.7.4 不再让它们参与变量判断或补丁生成：

1. 从上一楼变量快照开始重放原更新，再把整个回合所有变化重新计算一遍。
2. 要求变量模型输出“完整回合替换块”，而不是针对当前 `stat_data` 的最小纠正补丁。
3. 把模型补丁、脚本推导差异和原更新合并成第二份“标准答案状态”。
4. 用脚本自建的路径模拟器、类型裁判、完整状态 diff 和多层语义门禁决定模型是否正确。
5. 为了替换整块而重写正文中原有的完整 `<UpdateVariable>`，再重放一次全部 delta / insert。
6. 把人物档案根、数据库状态、世界连续性或 Doctor 内部任务状态带进变量模型，让一个调用同时裁决多个所有权域。
7. 因任一非关键格式细节不满足就整轮失败，或把“模型宣称无错”直接登记成检查成功。

保留的只有宿主安全所需的身份核对、一次官方解析、一次持久化读回、最小 WAL 和可见恢复。它们不得演变成新的变量语义引擎。

## 明确不照搬的 Story Oracle 部分

- 独立侧聊窗口、侧聊历史、模式房间、人格皮肤和诊断对话产品形态。
- 自建 OpenAI 直连、Profile 连接、流式侧聊传输及连接设置 UI；Doctor 继续使用自己的统一模型路由。
- 世界书编辑器、剧情参谋、弧线编译、角色工坊和正文校正。
- 校正稿作为新 swipe 的整篇正文改写；变量医生只写结构化更新与必要状态栏占位符。
- `message_id: 'latest'` 的宽松目标方式；Doctor 必须使用捕获身份。
- 自动诊断在模型没有输出 `<UpdateVariable>` 时把结果记成 `nochange` 的缺陷。
- Story Oracle 的完整 MVU 快照撤销；Doctor 使用事务最小快照，避免覆盖后续合法变化。
- `story-oracle_mvuguard2_旧尝试.zip` 中的本地补丁模拟器、完整原子门禁和二次自动修复调用。该包已明确标记为旧尝试，不是 Story Oracle `v1.35.4` 的成熟主链。

## 所有权边界

- 预设：正文生成前的创作约束、视角、篇幅和人物首次出场。
- MVU：实时变量状态及官方更新解析。
- Doctor 变量阶段：正文后的单次诊断、必要修复、持久化确认、刷新、重试和撤销。
- 人物档案：独立补全并原子提交，不依赖变量诊断是否有补丁。
- 数据库：继续从最终接受正文独立填表，Doctor 不竞争数据库表格。
- 世界引擎：独立记录和推进人物、势力、环境、任务与隐藏支线，不进入变量补丁。

因此，本版“参考 Story Oracle”具体意味着：复用它的窄输入、单模型判断、官方 MVU 应用和清楚的恢复语义；不是把 Story Oracle 整个扩展复制进 Doctor，也不是继续在旧完整替换架构上增加门禁。
