# 0.8.3 人物发现边界来源映射

## 真实失败

0.8.2 的真实首回合中，人物模型首次与定向修复两次都返回一张结构完整、两千余字符且可解析的档案；事务仍然失败，因为脚本把“手里拿着”和“手握着那”当成两个高置信人物名，强迫模型为动作短语建档。人物提交被阻断后，世界阶段也没有运行。

## 参考结论

- 旧 Doctor 的成熟人物主链明确声明 coverage 分片不是 NER；自由正文的人物发现由模型对完整接受正文输出结构化目标，脚本只验证结构和锚点。
- 数据库模板由填表模型从接受正文发现未记录人物，再依表结构写入，不用“任意中文片段 + 动作词”猜姓名。
- NPC Tracker 只更新已经注册的精确人物键；缝合怪只解析模型显式输出的结构标签。
- 本仓库 0.6.11/0.6.12 已记录同根事故：普通冒号、UI 文本和动作散文不能升级为确定性人物姓名。

## 0.8.3 最小修复

`highConfidenceCandidates` 删除全部自由散文发言者/动作主语正则，只保留：

1. 已持久化人物的 name/alias 在本轮正文中的逐字命中；
2. `NPC-数字` / `ACTOR-数字` 结构化编号。

首次人物仍由填表模型通读完整最终正文发现；正文没有明说的档案字段仍按世界观和上下文创造性补全。模型第一次返回空档案时，现有流程仍强制进行一次定向复核；返回人物时，完整字段、detectedCharacters 双向对应、原子提交与持久化读回标准均未降低。
