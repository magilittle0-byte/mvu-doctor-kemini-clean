# 0.6.13 运行时版本单一真值来源映射

## 真实失败链

0.6.12 已由扩展管理器更新到提交 `565ea31`。页面无缓存读取到的 `manifest.json`、`index.js`与`core.mjs`哈希均与该提交完全一致，但新 `index.js`仍声明`DOCTOR_VERSION = '0.6.11'`，面板也实际显示0.6.11。故障发生在新聊天和模型输入之前，页面已冻结。

根因链为：版本升级只修改manifest/package → `build-runtime.mjs`只替换内嵌core区块 → index头部版本常量保持旧值 → UI合同测试反而硬编码断言旧常量，导致`npm run check`错误通过 → 扩展管理器显示manifest版本而运行时面板显示旧版本，候选指纹无法形成单一事实。

## 成熟来源与采用方式

| 来源作品 | 完整阅读位置 | 成熟机制 | 本轮采用分类 |
|---|---|---|---|
| 旧医生 1.8.9 | `mvu-auto-doctor-reference-archive/03-reference-materials/tauritavern-knowledge/current/mvu-auto-doctor/tests/version-consistency.test.mjs` | 从`index.js`提取运行时常量，动态要求其与manifest一致，并要求package与manifest一致 | 直接复用测试合同；仅把常量名从`VERSION`适配为Kemini的`DOCTOR_VERSION` |
| 当前2.0测试线 | `mvu-auto-doctor-testing/tests/actor-profile-mvu-production-wiring.test.mjs`的`runtime diagnostic version exactly matches the install manifest` | 安装清单版本就是运行诊断版本，禁止两个版本真值 | 直接复用一致性断言，不移植2.0的发布门或运行状态 |
| 故事神域 | `mvu-auto-doctor-reference-archive/02-reference-code/world-engine/world-engine-ui.js`更新日志与manifest高亮合同 | UI展示版本必须和manifest当前版本匹配，不能由独立陈旧文本决定 | 原则复用：Kemini面板继续读取`DOCTOR_VERSION`，但该常量改由构建器从manifest生成 |
| Kemini现有自包含构建器 | `scripts/build-runtime.mjs` | 在不依赖宿主路径的前提下，把`core.mjs`编译进`index.js`并在check模式验证字节同步 | 最小适配：沿用同一构建器和失败语义，只加入版本读取、三方一致性门和确定性常量替换 |

## 直接保留

- `index.js`自包含内嵌core机制及其marker，不改变运行时模块加载方式。
- manifest仍是扩展管理器读取的安装版本，package仍服务本地构建与测试。
- 0.6.12的人物观察清理、模型全文发现、原子档案、变量医生和世界连续性逻辑原样保留。

## 最小适配

1. 构建开始先解析manifest/package，缺失或不一致立即失败。
2. 构建与`--check`都要求`index.js`恰好存在一个`DOCTOR_VERSION`声明，并将其确定性同步为manifest版本。
3. 独立测试动态核对运行时、manifest和package，不再把某个历史版本号写成“正确答案”。

## 必须新写及原因

- 旧医生没有Kemini的“现有index外壳 + 自动嵌入core”构建接口，无法原样复制脚本；版本替换必须嵌入Kemini现有`nextIndex`流程，确保自包含字节验证和版本验证使用同一个expected输出。

没有新增发布状态机、版本存储或宿主API；正式仓库、2.0测试线、预设和真实聊天数据不在本轮修改面。
