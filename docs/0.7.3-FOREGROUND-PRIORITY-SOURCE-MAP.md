# 0.7.3 正文生成优先与数据库式补档：成熟来源映射

## 本轮证据与目标

用户提供的 2026-08-29 最新跑团记录显示，同一助手楼层在更新 Doctor 后出现三次明显缩短的正文，并在重 roll 前等待旧 Doctor 结算。生成前注入同时重复了玩家输入、展开八张完整十四轴票据并要求正文输出票据回执；中文 `<本轮用户输入>` 包装没有被正确拆出，插件后缀还能进入当前动作。修复目标因此不是增加审查门，而是恢复成熟作品共同采用的边界：前台正文生成只接收必要的轻量提示，回复接受后再异步填表、检查和推进。

私人跑团文本只用于本地取证，没有写入仓库、测试夹具、提交信息或外部模型请求。

## 不得不新写的部分

1. **accepted 票据前台交接。** 现有 Clean 版有自己的 `pendingAcceptedFinal` WAL；旧 Doctor 和参考插件没有同名结构。新代码在抢占时先把未完成阶段保存为绑定旧正文的重试项，再关闭由旧 processing session 拥有的 accepted 票据，防止启动恢复把旧 Doctor 再次拉起。
2. **叙事顺序票据绑定。** 现有项目已经持久化完整十四轴票据，但不应继续要求正文输出 JSON 回执。脚本根据最终叙事里经人物发现确认的首次出场顺序分配；既有与权威人物跳过且不消费票据。历史补档只从失败任务中已保存的原票据重建来源账本。
3. **中文包装修复。** 旧正则错误地把 `\b` 用在中文标签名后，永远匹配不到 `<本轮用户输入>`。改为明确的标签属性边界，并丢弃闭标签后的插件后缀。
4. **已接受正文规划前缀清理。** 只在能证明唯一 `<content>` 边界时移除已知 planning/票据前缀；正文、选项和 `UpdateVariable` 原样保留。多义结构继续失败关闭。

本地配对预设为 247 个 prompt、214 个顺序项、34 个正则；0.7.3 文件与用户指定的最新版逐字节相同。旧 0.7.2 候选不再参与继承，原作者内容、A锁、篇幅、文风、选项、MVU结构与启用顺序均保持不变。该私有文件不进入仓库。

## 所有权保持不变

- 预设：正文生成前的篇幅、文风、视角、玩家自主权与首次出场表现。
- MVU：实时变量与当前状态。
- 数据库：独立表格与自身历史投影；Doctor 不竞争其表格。
- Doctor：接受正文后的结构/变量核验、完整人物补档、私密世界推进、持久化、恢复和诊断。
- 世界书/角色卡：固定设定和权威身份；权威人物不分配随机票据。

## 当前验证边界

自动回归覆盖前台抢占、同一 start token、内部 quiet STOP、真实 STOP、迟到 END、500ms fresh read、swipe 恢复、历史补档、权威人物、人物原子提交、世界单次推进、移动端 UI 合同和报告脱敏。它们只能证明受控环境中的代码契约；尚未完成当前源码指纹对应的真实 TauriTavern/SillyTavern 十二回合门禁，因此 0.7.3 仍是测试候选。
