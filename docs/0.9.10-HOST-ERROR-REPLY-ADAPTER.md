# 0.9.10：宿主错误文本不是剧情回复

2026-09-05 的 0.9.9 实机尝试没有生成正文：正文端点连接失败，宿主将以 `[API 错误]` 开头的 146 字错误说明作为助手楼落盘，并照常发送完成事件。Doctor 对它补写变量和两张档案，原版 World 推进一轮。这不是有效测试回合，也不能作为人物或世界能力通过的证据。

## 修改前核对的实际来源

| 来源 | 实际行为 | 本次处理 |
| --- | --- | --- |
| 当前 TauriTavern `/scripts/openai.js` 的 `sendOpenAIRequest` | HTTP 非成功及 `data.error` 抛错；成功响应中的错误说明文本仍走普通消息链 | 只兼容已观察到的错误信封，不修改宿主或网络路由 |
| Story Oracle 1.35.4 `runAutoDiagnose`、`autoApplyFix` | 无变量块仍从回复推导补丁，再交官方 MVU | 原件不变；不能把连接错误交给这条推导链 |
| 现有 Doctor `storyTransportErrorResponse` | 已识别模型返回中的中英文错误信封 | 原样提取信封识别部分复用到宿主输入；不新建语义审查器 |
| World 3.0.2 `onMessageReceived → runAutoEvolution → performEvolution` | 非空助手文本触发原生推演 | 原件不变；在已有 `evolve` 适配入口跳过宿主错误文本 |

自动完成入口以及现有手动检查/补档入口使用同一个错误信封判断。失败时保留原消息和历史存档，不调用医生模型、不执行 MVU 补丁、不补档、不推进 World；提示先重新生成正文。真正的正文没有变量块时仍按原流程检查和补全。

这项修复不解决正文服务的网络连接故障，不改变模型、API、预设、数据库、人格生成或世界推演架构。当前配对预设仍是本地 0.9.9r2。受控回归与真实十二回合结果分别报告。
