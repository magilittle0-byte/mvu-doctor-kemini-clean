## Current response-validation and retry path

`profiles/content.mjs` defines the whole-response parser path. `parseDiscovery` creates these global codes: `discovery_existing_profile_id_invalid`, `discovery_people_invalid`, `discovery_person_invalid`, `discovery_source_name_invalid`, `discovery_evidence_invalid`, `discovery_evidence_unbound`, `discovery_presence_invalid`, `discovery_player_forbidden`, `discovery_duplicate`, `discovery_existing_profile_id_duplicate`, `discovery_empty_reason_invalid`, `discovery_retire_invalid`, `discovery_retire_forbidden`, and `discovery_retire_conflict`. `parseProfileTurn` also creates `profile_turn_invalid`, `profile_turn_identity_reveal_invalid`, and `profile_turn_identity_reveal_required`. These are the intended value-free diagnostic whitelist because each means the complete model response failed a defined content or identity contract. `profile_materialization_invalid` and item-content validation errors are per-person outcomes and remain on the existing partial/repair path.

In candidate.8, `profiles/runtime.mjs:10-29` sends a special value-free feedback object only for `profile_turn_invalid`. Other whole-response parser failures reach the old retry loop, which attempts `parseDiscovery` on the stored raw response and returns only the retirement allowlist if it rejects the old response. `runtime.mjs:236-238` constructs the fresh manual request; the catch at `runtime.mjs:301-312` persists `review.failure.code` and `message`, and the raw model response remains in the request log. In particular, `discovery_evidence_unbound` can carry a source name in its stored error message, so only a fixed code and fixed explanation may be forwarded. Neither `request.raw` nor `error.message` is safe feedback.

The one generic correction path looks up the saved error code in a single immutable code-to-explanation map. It attaches that code only for the exact failed branch with matching receipt identity and MVU hash, and only while the parser inputs it describes—`narrative`, `players`, and `profiles`—are unchanged. Authority/world/global-prompt changes do not invalidate a fixed parser-class diagnostic; the retry still reads and sends the current full authority. This diagnostic gate is distinct from completed-result reuse, whose full input hash still includes authority and every other field. If a recognized global parser failure belongs to changed parser input context, the helper returns only the retirement allowlist and must not fall through to the permissive old `parseDiscovery` raw-candidate fallback. A stale receipt, non-parser runtime/transport failure, or unlisted code gets no parser diagnostic. The full exact retirement allowlist remains unchanged. The map describes only the failure class and asks for a fresh response under the existing contract; it supplies no rejected values and changes no validation rule. A partial result continues through the existing parsed-result and per-person error feedback.

## Mature value-free feedback pattern

P1's `modular/variables/module.mjs:147-161` binds retry feedback to the current identity, scope, pre-write state, prior state, and rule/schema/config hashes. When the dynamic context changed, P1 suppresses the old candidate and only emits selected stable diagnostics, such as `patch_structure_loss` or official failed-operation paths. `module.mjs:185-200` constructs those details from validated local structures rather than arbitrary model text; `module.mjs:237-242` records bounded feedback or a stable fallback code. P2 adapts the same boundary: stable parser-code whitelist, fixed explanation, no raw text or arbitrary `message`, and no diagnostic when parser-relevant input changes.
