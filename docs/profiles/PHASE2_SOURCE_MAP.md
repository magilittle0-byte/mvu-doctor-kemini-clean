# 人物档案模块：独立接入与复用来源

## 0.1.0-candidate.5 本轮误建档案的明确剔除

真实组合测试在第4轮发现模型把两个实际人物共用一份档案；既有按钮只点击一次，实际增加两次人物请求及一次世界跟随请求，未修好合并。本次模型仍主动返回了原群体，不能将该结果说成“模型剔除后被代码保留”。另经完整代码审计确认：手动发现提示允许剔除候选，解析器和保存路径却没有对应删除操作。这是修复机制的能力缺口，不以反复生成替代修复。

修改前核对 `profiles/ui.mjs` 按钮、`entry.js` 转发、`runtime.mjs` 的 retry/execute/发现/批量填写/逐人提交/召回，以及 `profiles/store.mjs` 的 revision、事务读回和失败补偿。旧参考 `profile-engine.js` 的 `dropUntargetedCompleteProfiles`、`dropProfilesOutsideCurrentReply` 只过滤本次返回，`storeAfterProfileRun` 仍从 before 追加，不能当成已存在的删除机制。沿用其中的版本核验、完整前态与保存收据；不增加存储后端或额外模型请求。

手动发现沿用同一个按钮和两次请求预算，增加显式 `retireProfileIds`，并说明人物条目必须对应可区分的单人，不能让群体共用个人身份与人格。本轮可剔除 ID 由当前目标的本地创建来源及前一分支基线确定；模型不能扩大列表，不能删除前轮人物，也不能同时更新和剔除同一 ID。没有返回某人并不等于删除。自动发现提示保留原字节，旧模型返回不含新字段时按空列表处理。

剔除计划先留在本轮 review，只有替换档案全部成功（或合法空名单仅剔除）后，才在最终同一快照提交中移除明确误建记录并保留检查所需前态。下一次修复只执行该次明确返回的列表，不能将上次失败的剔除计划自动累加执行。部分失败、网络失败、过期收据和保存失败不能提前删除原档案；成功兄弟仍沿用逐人保存。底层 `modular/store.mjs` 的 `store_write/store_readback` 会经过现有失败补偿；退休最终提交失败时先恢复过滤前的本地草稿，防止错误处理再次保存已经剔除的草稿。P1、世界推演、路由、字段完整性和自动调用上限不改。

允许名单只进入手动发现反馈，不增加自动批量生成材料。本轮创建来源跨同一收据的重复修复保存；省略某个本轮新 ID 不会让它永久失去后续明确修复资格。旧存档若没有本轮基线且没有前一分支可核对，或变量收据已经变化，则保守拒绝退休，不能猜测删除范围。

当前在隔离工作树实现，旧锁和旧回合仍只证明旧候选；candidate.5 尚未完成真实门禁，不能凭离线测试重新锁定或宣称可用。

## 0.1.0-candidate.3 召回等待已有完成收据

真实组合运行中，数据库辅助请求的 GENERATION_ENDED 早于主正文请求，人物资料虽已准备却被提前清空。当前 `profiles/runtime.mjs` 的 END 监听是故障点；这是代码时序缺陷，不能用重新生成掩盖。

修改前重新检索旧医生、数据库、NPC Tracker、Story Oracle 及相关历史材料，并完整读回当前 profiles runtime/host、modular runtime/host/entry。直接复用 P1 `subscribe` 的完成收据和 P2 `assertReceipt`：P1 已负责消息类型、END/RECEIVED 汇合、500ms 和 150ms 两次正文读取、scope/index/swipe/identity 与变量存档核验。P2 无需复制这些判定或调用旧 Doctor 的 waitForTargetSettled。

最小适配仅把召回结算从全局 END 移至 execute 首次 assert 成功之后。当前 generation 的 scope、baseline 楼号规则须匹配收据，保存 targetIdentity/scopeKey，review 只引用同一目标。正常生成必须包含 baseline 后的新用户楼和新助手楼；续写、重生成和 swipe 按冻结 P1 的同楼规则。START、停止、编辑、切聊、删除及卸载仍清理自己的旧提示。P1 失败时保留至现有按钮重试成功或下次失效事件；没有新增重试、轮询、消息判定器或模型调用。

NPC Tracker 的独立提示 key 和清空方法继续复用，其全局 END 清理不适合多辅助请求的宿主，故不继续照搬。旧医生的目标结算和数据库 waitForTargetSettled 说明下游应等权威完成；旧世界多阶段召回账本不适配本模块，未引入。promptObserved 仍只证明提示中观测到整段资料，semanticConsumptionProven 保持 false，真实主请求与正文消费须独立核对。P1 和 P3 文件不改；旧 P2 锁与验收只属于历史候选，新候选尚未完成真实门禁。

真实发现结果多次在格式合法时遗漏正文中已提及人物；现有按钮只重发同一提示，结构修复分支没有触发。本次最小改动只为主动retry添加上一份发现结果和重新核对说明。它是对修复机制的改进，不把模型遗漏伪称为解析器故障，也不要求模型永远零幻觉。

应用前重新检索并核对旧Doctor、数据库绑定/模板、Story Oracle、变量反馈、人物staging及糖糖/Izumi/缝合怪/Z论坛相关来源。直接复用当前 `profiles/runtime.mjs` 的请求留存、当前receipt、取消、parse/binding、单人物生成和store/readback；参考既有discovery/profile repair携带原结果与错误的顺序。旧 `profile-engine.js` 的 `minimumNameCount/preserveNames` 属于不同schema，不搬入本模块，避免强制保留错误候选。
