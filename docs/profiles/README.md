# 人物档案模块 0.1.0-candidate.2

这是人物档案手动修复的更新候选，尚未完成当前版本的真实门禁。第一阶段变量修复 0.10.26 保持锁定。原人物版本的锁定记录保留为历史证据，其文件指纹不代表本候选已通过；世界模块在人物模块重新验收并适配依赖前暂停接入。

安装仓保持为 `magilittle0-byte/mvu-doctor-kemini-clean` 的 `main`。先通过扩展管理器更新同一安装目录，再将 `profiles/install.json` 导入酒馆助手全局脚本并启用，重新加载页面。人物模块和变量模块各有独立面板。自动建档及相关档案召回默认开启。

普通正文完成、变量模块完成保存读回后，医生自己发现人物，用正文、MVU、角色卡和世界书生成完整档案。预设无需输出专门的档案标签或票据。每个人包含36项文本和8项列表，表格索引与展开详情读取同一份存档。姓名相同不会由脚本直接合并；已有身份由模型依据记录对齐，新增人物由脚本分配独立ID。

格式或缺项先自动定向补填一次。一个人物失败时保留旧完整版本，其他成功人物仍会保存。点击“修复本轮档案”会重新读取当前正文和已确认变量，进行新的发现和生成。同一变量证据和MVU下，上次仍能通过当前正文绑定校验的发现结果会作为待纠错材料带入，要求重新通读正文中的人物提及，补漏并纠正误识别；旧结果不是事实或指令。变量证据变化时不携带旧结果。原自动建档提示、44字段校验与保存读回流程保持不变，不需要填写姓名或额外审核。生成式模型仍可能误认身份、漏人或设计不合适的内容，按钮不保证单次就消除幻觉。

换聊天、改正文或开始新生成时，旧任务停止写入；档案按聊天分支保存。取消和关闭自动建档不删除已有完整档案。相关人物资料会进入后续正文提示，私有背景仅供对应NPC塑造，不代表玩家或其他NPC知道。注入观察与正文是否正确使用分开核验。

人物模块只写自己的IndexedDB命名空间和自己的召回提示，不接管数据库表格、不写MVU、不执行世界行动。每份正式档案必须先完整生成再保存读回；失败候选与模型原文仅保存在用户本机模块记录里。

开发检查：`node scripts/check-profiles.mjs` 同时校验P1的17个运行文件与11个保护文件、P2安装包和源码指纹。`node --test tests/profiles-*.test.mjs` 是受控检查，不代表真实宿主验收。阶段锁定仍须完成同一新聊天十二回合的实际人物、变量、表格、召回与完成态读回核验。
