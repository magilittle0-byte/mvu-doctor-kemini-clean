# 0.8.8 人物档案占位词边界来源映射

## 真实失败

0.8.7 在真实 TauriTavern 的同一全新聊天中，第 1 回合完整通过；第 2 回合人物阶段失败，世界因此没有提交。脱敏结构取证证明两次模型返回都包含完整 `identity.occupation` 字符串：字段长度为 20，包含职业职责信号，“未知”位于索引 7，既不在开头也不在结尾。失败来自 0.8.4 适配层把禁用词在字段任意位置出现都当作空值，而不是模型漏字段、解析失败、行绑定失败或持久化失败。

私人正文、人物姓名、档案内容、提示词和模型原始返回只在本机核对，没有写入仓库或提交。

## 最小适配

`PROFILE_PLACEHOLDER` 的“任意位置命中”改成 `PROFILE_EDGE_PLACEHOLDER`：

- 禁止占位词作为独立答案落在字段开头并后接结束或分隔符，仍判不完整；
- 禁止占位词作为答案落在字段结尾，即使带引号、括号或常见标点包装，仍判不完整；
- 字段中间用“未知”修饰一个对象，但整句已经给出具体职责、身份或行动内容，不再误判整项为空。

新增真实浏览器回归同时锁住两端：旧的开头/结尾占位用例仍必须触发唯一修复；合成职业句“负责追查未知来源信号的前线侦察员”必须无需修复直接原子提交。

## 明确没有新增

- 没有第二个修复调用、字段级重试、状态机或新的持久化表；
- 没有删必填字段、接受空字符串、降低完整性或硬编码真实档案值；
- 没有修改 Story Oracle、World Engine、Life State 冻结原件；
- 没有修改用户私有 Izumi 预设、数据库或 MVU 所有权。

0.8.8 仍是 Kemini Clean 测试仓候选。自动检查不能替代当前源码指纹的真实 TauriTavern 十二回合验收。
