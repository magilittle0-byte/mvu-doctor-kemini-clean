# 0.9.2 移动端布局来源映射

## 真实失败

0.9.1 在全新真实酒馆聊天发送首回合前执行 390×844 检查时，Doctor 面板本身位于可视区内，但第五个标签超出标签栏并出现横向滚动。旧验收脚本还把宿主页面的 1280px 文档宽度归因给 Doctor，并在“诊断”页测量隐藏的“总览”按钮，形成两项误判。该聊天没有发送私有首回合输入，计数为 0/12，不能作为任何功能通过证据。

## 原样保留

- `legacy/0.7.5/style.css` 的五标签网格信息架构、内容区 `overflow-x: hidden`、移动端安全区和不小于 44px 的触控目标。
- `vendor/world-engine-v3.0.2/style.css` 的 `repeat(..., minmax(0, 1fr))` 等宽收缩网格模式。
- `vendor/life-state-v5.35/life-state-v5.35.js` 的窄屏媒体查询、面板内纵向滚动及移动端网格降列模式。
- 0.9.1 的变量证据链、人物档案、原生 World 所有权和宿主生命周期全部不变。

## 最小适配

| 机制 | 成熟来源 | 0.9.2 适配 |
|---|---|---|
| 五标签布局 | 旧 Clean 的五列标签网格 | 680px 以下改为三列等宽网格，自然形成 3+2 两行；没有新增导航组件或状态 |
| 可收缩单元 | World 3.0.2 的 `minmax(0, 1fr)` 网格 | 标签按钮增加 `min-width: 0`、允许换行并取消省略裁切 |
| 手机滚动边界 | 生理状态引擎 ver5.35 的面板内滚动模式 | 禁止标签栏横向滚动，保留 Doctor 内容区纵向滚动和 44px 触控目标 |
| 真实验收测量 | 现有 0.9.1 CDP 驱动 | 先切到总览并等待重绘，只测 Doctor panel/nav/overview；实际滚至底部并确认最后操作按钮可见 |

## 明确未改

- 未修改 Story Oracle、World Engine 或生理状态引擎冻结原件的任何字节。
- 未修改变量提示、人物提示、模型路由、人物档案、世界推演、注入、持久化、重 roll 或数据库边界。
- 未用宿主整个页面的横向宽度替代 Doctor 面板自身的布局证据。

## 验证边界

浏览器回归固定使用 390×844，要求五个标签全部位于 Doctor 标签栏和面板内、文字不被裁切、panel/nav/overview 均无横向溢出，并确认 overview 存在纵向滚动且最后一个操作按钮可达。该回归只能证明 DOM/CSS 布局；0.9.2 仍须以当前源码指纹在全新真实聊天完成十二回合功能试跑。
