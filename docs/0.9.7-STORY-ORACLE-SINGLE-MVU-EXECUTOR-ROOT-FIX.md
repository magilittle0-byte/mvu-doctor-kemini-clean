# 0.9.7 Story Oracle 单一 MVU 执行器根修

## 真实失败与根因

0.9.6 的真实新聊天首轮中，正文原更新包含向普通对象插入一个物品。宿主最终 MVU 已包含该物品，Doctor 返回的最终状态与固定楼层的新鲜宿主读回也完全一致；人物档案同时完整生成并原子提交。失败不是变量未写入，而是 0.9.5 新增的本地逐操作模拟器拿“原始 insert 值”与“官方 MVU 经 schema 模板归一化后的对象”做严格相等比较，把真实成功误报为 `unapplied`，继而生成 `partial` 状态并拦住验收流程。

这属于所有权错误：官方 MVU 会执行路径修正、schema 约束、模板应用、ValueWithDescription 和数值／日期规范化，本地影子解释器无法可靠复现这些语义。继续为每一种归一化加特判只会制造第二套 MVU。

## 成熟来源映射

| 能力 | 成熟来源 | 0.9.7 采用方式 |
| --- | --- | --- |
| 一次诊断 | Story Oracle v1.35.4 `buildDiagnosePromptFrom` 与 `runAutoDiagnose` | 继续直接调用原件的上下文、提示、运输和更新块提取；模型只返回一个最小纠正块 |
| 唯一解析／执行 | Story Oracle v1.35.4 `autoApplyFix` | 原样保留 `Mvu.parseMessage(patchBlock, oldData)`；候选等值则零写入，有变化才调用 `Mvu.replaceMvuData` |
| `insert`、模板和 schema 语义 | MagVarUpdate b428179 `extractJsonPatch`、`updateVariables` | 不再复制或模拟；完全交还官方实现。对象键插入、数组位置、模板补齐与 schema 归一化均以官方候选为准 |
| 固定楼层与写后读回 | Doctor 既有宿主适配层 | 最小保留：消息／swipe 身份复核、写前陈旧检查、固定楼层写入、完整候选同楼读回、失败回滚 |
| 运输错误、手动复检和界面刷新 | Story Oracle 原件加 Doctor 固定目标适配 | 保留；这些只处理运输、恢复和用户可见投影，不解释 JSONPatch 语义 |

## 删除内容

`profile-engine.js` 删除以下 0.9.5 新增机制：

- 从上一助手楼读取变量前态并重放正文原补丁；
- `simulateDiagnosisOperation` 本地 JSONPatch 执行器；
- 对 `replace`、`delta`、`insert`、`remove`、`move` 的本地操作回执；
- 将本地模拟结果与官方整批结果逐路径严格比较；
- 依据影子结果剔除操作、生成安全子集并第二次调用 `Mvu.parseMessage`；
- `partial` 变量判定和由此产生的警告终态。

因此变量阶段现在只有一次模型调用和最多一次官方 `Mvu.parseMessage`。报告继续保存模型原始返回、补丁、固定楼层身份、官方结果类型和最终 MVU；`semanticProof` 仍为 `false`，不会把模型的空补丁说成脚本独立证明正确。

## 未改变的边界

- 预设继续负责正文生成前的文风、篇幅、首次出场和玩家自主权。
- MVU 继续独占实时变量解析和状态写入语义。
- Doctor 只在正文后调用 Story Oracle 诊断、按需提交官方候选，并独立完成人物档案。
- 数据库继续独立填表，Doctor 不写数据库表格。
- World Engine 3.0.2 的原生生命周期、解析、存档、checkpoint、重 roll、注入和 UI 未修改。

## 验收边界

本地回归覆盖官方 MVU 单次解析、对象 insert 已被 schema 归一化时的零写入、固定楼层读回、数组 insert、数值／日期 delta、人物阶段继续执行以及影子执行器源码不存在。它们只能证明代码结构和受控行为；运行代码变化后，0.9.6 的真实结果全部失效，0.9.7 必须从全新聊天重新开始连续真实回合测试，未完成前不得声称正式可用。
