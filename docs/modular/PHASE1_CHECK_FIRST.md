# 第一阶段：先核对字段条件，再比较状态差额

0.10.21 第四轮真实验收失败：模型依据独立背景记录补齐了尚未满足所属范围或获取条件的字段。官方解析、UI和存档均保存了这些错误，执行成功不能证明语义正确。

## 来源与最小适配

- Story Oracle v1.35.4 的 DIAGNOSE_SYSTEM_PROMPT 与 buildDiagnosePromptFrom：原卡路径、类型和 check 定义字段权限，诊断只修实际差额。原件和调用保持不变。
- 数据库 spv8.4 的 prepareAIInput_ACU、目标表 sourceData 的 Note/initNode/insertNode/updateNode，以及分组统一提交：先按目标表自己的操作条件解释资料，再生成该表操作。完整来源已在本次本地审查中阅读；其 SQL、数据库任务类别及初始化时机不移植为 MVU 规则。
- 当前 groupInstruction/groupRuleMaterial：已提供完整原规则与当前值。本次仅替换既有核对顺序段，要求先引用决定范围和时机的原句，再核对事件条件，最后比较差额。正文、面板、数据库中的同类名称不能自动证明目标路径条件成立。

保留全部背景、历史、数据库资料、原卡结构、消息角色、唯一末尾任务、规则授权的创建能力和原有分组。未新增场景关键词、字段白名单、第二语义审查器或本地 MVU 执行器。新增文字用于连接字段原句与检查顺序，不冒充第三方原样提示词。

## 验证边界

同一真实失败现场、同一当前模型的两个只读请求纠正了原误判；没有执行或保存返回补丁。这只是定位证据。快速检查也不代替验收，0.10.22 必须以当前源码从一个全新聊天重新完成十二个正常回合及协议要求的压力覆盖，再做完成态刷新读回。人物档案与世界引擎尚未开始，变量模块未锁定。
