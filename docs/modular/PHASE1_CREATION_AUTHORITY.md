2026-09-08 修改前来源映射。0.10.15 与完整 0.10.14r1 预设的真实首轮已经拒绝：玩家提交完整创建档案并明确要求按该档案登记，姓名字段仍保留前态默认值。Doctor 的第三组将其与其他头部字段合并判为正确，返回空补丁；所有八组实际请求均含完整创建输入，不是历史正则再次丢失文本。其他三项修复已由官方执行，完整变量与原生磁盘一致，仍不能抵消姓名漏修。

## 本次重新检索及实际读取

- 全项目与历史归档重新检索默认身份、姓名初始化、用户设定和填表路径，覆盖旧医生、故事神谕、数据库及模板、LifeState、糖糖、Izumi、缝合怪、角色卡与诊断资料。只将实际相关实现作为来源，不凭文件名声称复用。
- 完整阅读当前 `host.capture/contextSnapshot/previousMvu`、`transcript.userInput/diagnosisTranscript`、`composeDiagnosisMessages`、分组与模块调用、官方解析及持久化。实际模型请求中的创建输入完整，归属组未发出该字段操作；解析层没有吞掉补丁。
- 阅读 Story Oracle 1.35.4 的完整 `DIAGNOSE_SYSTEM_PROMPT`、`buildDiagnosePromptFrom` 与当前适配调用：以本卡字段定义和对话为依据，逐项修正真实差额，保留最小官方补丁；阅读原件 `buildDirectiveRaw`，确认规划不压过用户选择。后者不接入变量模块。
- 阅读数据库 spv8.4 默认主角信息表的身份说明、初始化与后续更新定义，以及完整 SQL 填表提示构造。它将主角创建登记与之后的状态变化分别描述；数据库自己的表结构和 SQL 不适用于 MVU，不予移植。
- 当前卡全部十二页变量规则在本机完整核对：姓名仅在创建时设定，基础分配与天赋创建另有各自触发，装备需实际获得等事件。创建档案中的明确登记不是单纯署名，也不要求正文再次复述才有效。未知人物发现器的逐字称谓要求不适用于玩家的明确创建输入。
