# 数据库固定记录说明的医生投影

0.10.18 的真实第四轮仍在引导场景。数据库可读背景记录包含引导任务，医生将其写入要求进入副本后才初始化的当前副本任务。完整变量、实际卡片界面与原生存档均确认错误，当前候选已拒绝，前三轮不能跨候选累计。

## 来源与实际边界

- 数据库 spv8.4 的 `formatJsonToReadable_ACU`（16485–16544）生成普通表格文本；完整 `updateReadableLorebookEntry_ACU`（27384–27789）在独立保存后的表值外生成 WrapperStart、ReadableDataTable、WrapperEnd。27602 的固定 WrapperStart 声明记录高于任何背景设定，与真实输入来源逐字匹配。
- 生成条目识别（20442–20514）、完整背景选择和读取（28405–28661）、`prepareAIInput_ACU`（23033–23280）、统一提交（45571–45822）已核对。它们按数据库自己的表、条件和写入范围工作。不能整体删除这些表格来处理说明中的越域指令。
- Story Oracle 1.35.4 的原生 `buildWorldInfo`、规则收集和 `stripMvuRuleContents` 维持资料读取，并使用已知内容边界隔离特定机制文本。原版没有本次数据库说明适配，不能把新说明称作原件提示。
- 当前 Doctor 的数据库用户包装投影同样保留原始聊天与其他消费者。此次只沿用这种局部投影边界，不使用用户标签解析世界书，也不增加并行状态机。

## 改动

原样复用完整原生世界书扫描、全部表值和历史、原始规则、模型连接、分组、官方 MVU 执行与存档。只在现有 `composeDiagnosisMessages` 的 `worldContext` 插值中，对已确认的固定 WrapperStart 全文作精确替换。保留标签、其他字节以及未知/相似说明；重复的已知包装统一处理。

替换说明标明数据库记录是独立事实参考，不能改变 MVU 字段的路径、结构、所属范围与触发条件。卡片、历史、本轮输入、正文、规则和全局自定义提示不被此投影改写。数据库本体和预设仍收到原来的内容。

新写仅是已知生产者固定文本的投影接缝，因为该包装面向正文生成的优先级不能直接移植为变量裁决权。`contextHash` 继续指向原生源上下文；复核中的 baseMessages 和每组 messages 保存实际发出的投影材料。没有把源哈希冒充模型请求哈希。

## 验证范围

同一冻结失败请求的第一组只替换这一处说明，当前真实模型返回空补丁，明确当前场景未触发副本字段。其余请求字节全部相同，聊天、MVU与配置未改，返回未执行；完整原文已读取并清理临时图。该只读定位只支持候选方向，不能证明正常运行成功。
