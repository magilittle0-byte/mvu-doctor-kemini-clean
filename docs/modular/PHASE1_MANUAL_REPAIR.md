# 手动修复与自动检查开关

0.10.26 修复一个控制链缺陷：关闭“自动检查本轮变量”后，手动“重试本轮”也被入口开关拦截；正常正文完成后还可能停在“正文生成中”，使按钮不可点；变量快照变化的重读又会丢失手动模式。

现在开关仅控制自动调用。自动跳过后显示可手动检查；手动重查仍绑定当前正文和当前变量，并在快照变化时保留手动模式。取消、聊天/楼层/swipe绑定、官方解析与原子保存读回继续生效。

## 实际复用与适配

- 旧 MVU Auto Doctor 的 `runTarget()` 使用 `!manual && !settings.enabled`：按当前模块的 `reason` 参数最小适配这一条件。
- 本仓 `legacy/0.7.5/index.js` 的 `manualVariableRecheck()` 及其按钮入口，使用新 epoch、当前目标和明确 manual 模式；当前模块已有的同类捕获和取消链继续使用。
- 原版 Story Oracle 的 `postReplyPlan()` 与诊断模式按钮将自动开关和手动诊断分开；原版核心保持原样。
- 新写仅为当前模块的自动跳过状态提示和已有重读调用的模式传递；没有新调度器、补丁执行器或按钮。必要回归使用现有模块测试框架。

## 验证边界

模型可能误判。遇到模型内容错误时，使用修复按钮重新读取正文与MVU、重新调用当前模型，再核对修复结果；不能把一次误判自动转成代码或提示词修改。实际控制、解析、目标绑定和保存错误仍须修代码。

0.10.25 的真实同回合按钮检查已确认新模型调用、新写前快照、新结果记录、存档读回和按钮恢复，没有重复执行补丁。该次原状态正确，因此不能声称证明了实际幻觉恢复，也不能替代0.10.26的真实验证。
