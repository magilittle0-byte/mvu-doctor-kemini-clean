# 复杂容器独立核对

0.10.19 首轮真实核验拒绝：模型读到已发生交互，却为系统实体自行豁免关系登记。原卡完整规则没有此例外，完整变量、实际界面与原生存档都显示遗漏。包装说明未在本轮出现，不能把这次结果说成该适配已验证。

## 来源与定位

本轮重新检索整个项目的旧医生、数据库/模板、Story Oracle、糖糖、Izumi、缝合怪、Z论坛和卡片/规则/前端/报告。完整读取当前范围规划、组材料、模块调用，以及数据库的 `compatibilityKey_ACU/buildGroup_ACU`、`prepareAIInput_ACU`、请求组装和 `processGroupedRuntimeChunk_ACU`。也回看已经失败撤回的角色切分、编号覆盖和提示替换，未重新引入。

数据库按 `sheetKeys` 指定每组独立工作，读取同一快照，统一提交。其 `batchSize` 是聊天批次；原件没有按 MVU 字段复杂度分组的算法。当前适配把八个互不重叠的路径范围分在一起，一个含大量子项的对象也仅计为一个范围。

真实样本有 64 个范围，26 个对象/数组、38 个标量。首组材料为 2747 字符，第二组为 5219 字符；13558 是完整规则长度，不是首组长度。单个范围可以包含大量叶字段。这个结构事实不能独自证明模型内部的遗漏原因。

在同一冻结首组请求上，仅用现有组指令和规则材料函数单独指定关系范围；背景、输入、正文、完整规则和前后态全部保留。当前同一模型补出了遗漏的中立交互关系及明确创建资料中的既有关系。完整返回已本机阅读，未执行，聊天/MVU/设置未变；只读定位不计入验收。

## 最小适配

- 原样保留路径声明展开、父子裁剪、数组整体归属、错误父容器修复范围和所有待核对路径。
- 新写仅是既有 planner 最后组装步骤：当前或前态为对象/数组的完整范围各占一组；其他范围按原顺序最多八项一组。容器内部不拆分，不按人物名或具体卡片路径分类。
- 保留原有全部输入、提示文字、模型配置、越界保护、有限重试、官方一次解析和统一提交。没有增加语义审查模型、答案模板或人物发现器。

此样本预计由八组变为三十一组，耗时与模型请求量会增加。它是让模型逐个关注复杂范围的候选，不能预先承诺无误。0.10.20 仍须新指纹、新聊天十二轮、压力覆盖、逐轮变量/UI/存档核验及最终刷新。人物与世界模块未开始，三个模块未锁定。
