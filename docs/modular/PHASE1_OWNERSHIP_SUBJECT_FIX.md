# 第一阶段：限定前端权限声明的主语

2026-09-06，修改前来源记录。0.10.6真实首轮已失败；只改变消息角色的一次只读对照也没有修复漏项，并新增算术和类型误判，故不采用该对照作为成功方案。它未写聊天或变量，不计验收。

核对实际规则、当前policy与完整compileOwnership/checkOwnership/module调用链发现确定的脚本错误：编译器把整句中被提及的字段都当作前端所有。例如“态度由前端根据信誉值计算”会把输入信誉值也锁住；“转职时更新名称、品质，职业等级重置由前端处理”会连名称与品质一起锁住。另有同一属性组中“实际值也由前端自动合成”的明确声明，因候选路径只包含加成叶子及其兄弟，漏掉父组下的实际值容器。这与模型漏审是不同问题，必须同时如实保留后者未解决状态。

已重新搜索当前实现、旧医生、2.0、完整参考归档及数据库源码的权限解析机制，只有当前最小适配有路径/check声明编译器。官方MVU是唯一更新执行器；原版Story Oracle把卡片规则给模型，没有可直接移植的中文字段所有权编译器。数据库只按自有表模式验证，不能接管MVU规则。因此保留原有编译器、作用域候选与官方单次解析，最小修正其明确声明识别，不另造执行器或剧情语义审查。

最小适配：先去掉括注并按标点分出声明从句，只取“由前端/脚本…”或“前端托管”前的字段主语，后面的计算输入不算所有者；同句其它AI动作不继承该权限。先在原有最近路径范围匹配；仅当无匹配时，检查上一层同组容器以处理明确的派生输出声明。禁止全局同名封锁。没有明确字段名的“本变量/由前端…”仍只绑定声明路径。

直接复用：core.mjs现有路径展开、JSON指针、祖先覆盖与insert叶子检查；module.mjs事务、重试和官方MVU解析不变。新写：声明主语提取和最近作用域回退，因为旧编译器没有这些必要边界。回归使用合成规则复现输入/输出、转职子句和同组派生字段，不写私人正文或人物数据。此修复不能代替新候选真实十二轮验收。
