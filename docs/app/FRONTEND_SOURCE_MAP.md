# Unified Doctor surface source map

Scope: add a discoverable shell around the current variable, profile, and world module UIs. The shell only reads their public status snapshots and moves their existing DOM nodes; it does not start a module or invoke a model.

1. **Real path and fault:** users need a visible entry and one place to reach the three existing panels, while the panels currently live under `extensions_settings2`. The current P1 note saying profiles and world are “not made yet” is stale in this three-module checkout.
2. **Mature sources:** the previous unified surface is `profile-engine.js` (`panelHtml`, `ensureUi`, `render`, around lines 6467–6635) with the root `style.css`; current module surfaces are `modular/ui.mjs`, `profiles/ui.mjs`, and `world/surface.mjs`. Their entry/runtime contracts are exposed through `window.MVUDoctorModular`, `window.MVUDoctorProfiles`, and `window.MVUDoctorWorld`.
3. **Reuse as-is:** preserve the legacy launcher and panel IDs (`mvu-ref-launcher`, `mvu-ref-panel`), visual viewport sizing, close button, and base CSS. Move the existing module elements into page containers so their original buttons, profile index/details, world record, and settings retain their own event handlers.
4. **Minimal adaptation:** provide five shell pages (overview, variables, profiles, world, settings), status summaries from the three public `status()` snapshots, and a settings guide that points to existing configuration. Hide the stale P1 “not made yet” note while the shell itself reports each module's detected/loading state. This boundary leaves module state and actions with their original owners.
5. **New code and reason:** no current root entry owns a shared shell, and existing surfaces do not provide a combined overview or visible launcher. `app/surface.mjs` therefore supplies only the missing shell, including a low-cost child-list observer for late panel mounts/remounts; `app/style.css` imports the old base styles and adds only shell-specific layout. Moved module DOM keeps its original parent/position and is returned there on shell destruction when both nodes remain connected. No retry, refresh, polling, model call, or legacy engine is added.
