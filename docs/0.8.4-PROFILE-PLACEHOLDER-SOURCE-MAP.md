# 0.8.4 人物档案占位词补填来源映射

## 真实失败

0.8.3 当前源码的真实酒馆首回合生成了两张人物档案。其中一张的全部必填文本和数组都存在、序列化长度为 2139，但 `currentState.location` 在字段末尾保留“未知”，`currentState.emotion` 以“未知”开头。模型初始返回已经包含这两处，运行记录为 `repaired=false`、`initialErrors=0`，说明错误发生在提交前完整性校验，而不是持久化或前端刷新。

## 直接复用

- 来源：本仓成熟 0.7.x `core.mjs` 的 `EMPTY_WORDS`、`isNonEmptyText`、`meaningfulProfileListItem` 与 `profileCompletenessReport`。
- 复用内容：占位词后接括号、空格或常见标点仍不算完整；文本必须包含字母或数字；必填数组必须包含真正可用的内容。
- 复用测试语义：裸占位词、`未知（外观……）`、占位字符串数组和空对象数组都不得成为“完整档案”。

## 最小适配

- 当前 0.8.x 档案结构明确要求数组元素为自然中文字符串，因此把 0.7.x 的递归列表谓词收窄为“每个已提供元素都必须是可用字符串”；`aliases` 仍允许空数组。
- 真实失败还证明模型会把“未知”放在字段末尾。对生成提示已经明令禁止的 `未知、不详、待定、未登记、未设定、暂无、正文未提及`，在完整字段内任一位置出现都判为待补填，而不是只检查第一个词。
- 校验错误继续进入现有的单次完整对象定向修复；修复成功后才沿现有 metadata 原子提交与完整读回路径落盘。没有新增调用阶段、状态机、档案存储或字数门。

## 没有移植的内容

- 不引入 Actor Profile V6、ActorRef、并行批处理或额外调度器；当前失败不需要这些架构。
- 不修改冻结的 Story Oracle 1.35.4、Life State 5.35 或 World Engine 3.0.2 原件。
- 不让 Doctor 创作第二套人格；预设与生成前票据仍负责首次出场创作，Doctor 只补全并持久化人物档案。

本版本仍是 Kemini Clean 测试线候选。自动检查不能替代当前源码指纹的真实 TauriTavern 十二回合验收。
