# 0.9.5 World 原生任务槽与 MVU 回执来源映射

## 真实失败

0.9.4 的首轮真实酒馆候选中，World 的调用、JSON 解析、轮次递增与持久化均完成，却没有产生非玩家、势力或环境主体的本轮行动。它只把近期正文中的玩家旧背景重新写入 `blackbox`；问题不是 `blackbox` 不能保存 NPC 隐秘行动，而是 Doctor 把动态任务放进 Memory 资料槽，又没有要求区分旧背景与本轮已实施变化。同一轮的 MVU 修复还把一个有效纠正与一个不存在于当前 schema 的路径混在同一补丁里；只因整份状态发生过变化，Doctor 就把整批显示成“已修复并读回”。该轮因此失败，旧证据不得用于 0.9.5。

## 删除 0.9.4 的错误接缝

- 不再把 Doctor 命令或整批人物 JSON 追加到原生 Memory 上下文。
- 不再由 Doctor 重定义 `blackbox`；人物私密行动完全服从 World 原生的目击、痕迹、跨轮价值与传播规则。
- 不再发送最多 12 人／16,000 字符的静态档案。
- 不新增第二个世界 scheduler、世界 schema、存储、解析器或语义成功门禁。
- 不因一个合法操作改变整份状态，就把同批未落地操作一并标成成功。

## 0.9.5 的小接缝

World 每轮仍只执行原生的一次 `performEvolution`。Doctor provider 最多返回 2,200 字符：优先选当前原生未终局事件已关联的人物；否则从完整非玩家档案中按 World round 稳定轮换一名主行动者，并最多携带两名与其行动有关的人物。资料只保留目标、位置、有限知识、能力、资源、约束与少量决策轴。预算在逐字段序列化前计算，只加入仍能形成完整 JSON 的字段和人物，禁止从字符串中间截断。

本轮短任务要求 World 先估算经过时间，再从主体自身目标形成实际尝试并由世界裁决；旧背景不能复制成新变化，持续事项必须写入下一轮可读的原生字段。私密且尚无可观察后果的已实施行动进入黑箱，可观察进程才进入事件等字段。它不要求每轮制造大事件，不规定结果必须成功，也不替玩家行动。

## 验证边界

`UPSTREAM_SHA256SUMS.txt` 固定 World 提交的 45 个原始文件哈希；验证脚本用它独立核对 44 个未改文件，并另以当前运行哈希核对唯一适配文件。`SOURCE_CMP_REPORT.txt` 仅是适配前导入时的历史比对，不再被当作当前 45 文件全未修改的证明。

静态、Node 与无头浏览器测试只能证明来源接缝、操作回执和页面合同，没有证明真实模型质量。任何运行代码或提示词改变后，必须从一个全新聊天重新执行当前真实酒馆十二回合协议；完整通过之前只能推送到已授权的 Kemini Clean 测试 `main`，必须标为未完成正式门禁。
