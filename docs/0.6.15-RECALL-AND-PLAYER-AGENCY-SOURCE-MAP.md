# 0.6.15 当前行动召回与玩家意图边界来源映射

## 真实故障链

0.6.14真实酒馆第2回合已经证明：生成前准备了两条仅含公开投影的召回项，最终正文一条也没有采用，Doctor随后如实释放；同一正文还把玩家只做出的可观察动作解释成了输入中不存在的“想得到某种反应”。这不是解析或面板误报，而是生成前选择与预设接收两端的根因：召回器用包含历史/时间/旧召回的缝合整包计算相关性，且注入只有数据没有执行优先级；原Izumi适配源中还保留了授权补写玩家输入外行动和对白的启用提示对象。

## 直接复用的成熟合同

| 来源 | 直接采用的合同 | 本项目落点 |
|---|---|---|
| 缝合怪 `Stitches_RebornV_本体.json` | 当前行动与历史召回分开，人物只能从可观察行为解释，不能把动作擅自扩成输入外动机 | `recallSelectionInput()`只提取最后一段当前行动；本地预设最终输出协议增加“动作只等于动作本身” |
| Story Oracle 1.71 `buildDirectiveRaw/applyPlanInjection` | 注入不仅给数据，还直接声明执行要求、玩家动作优先、可见后果和一次性使用 | `formatGenerationInjection()`输出本轮动作边界、`required_once`、转场落地和防全知要求 |
| 2.0 `buildContinuityInjection` | 没有自然关联时允许零条；隐藏推进只把可观察入口交给正文，玩家自主权优先 | `selectWorldRecall()`取消普通无关输入的两条兜底；保留既有公开投影裁剪 |
| 糖糖公司适配预设 | 玩家A锁、NPC可以主动、候选不能替玩家执行 | 只在Izumi最终输出协议中补入动机边界，不把NPC自主性移交给Doctor |

## 最小适配

1. 缝合怪实际可能使用中文或英文包裹标签，因此提取器兼容 `<本轮用户输入>`、`<user_input>`、`<current_user_input>` 与 `<input>`，并以文本中最后出现的非空包裹为权威当前行动；没有包裹时原样使用酒馆输入。
2. Doctor现有公开投影与一次性预约结构保持不变，只给选中项增加公开调度字段：最强相关项为 `required_once`，同轮其余项为 `optional`。低信息“继续”只取最高优先项；普通无关动作返回零条。
3. 最终消费核验继续使用现有逐字/双字组可复算证据，但当存在 `required_once` 时，optional命中不再能把整包冒充为已消费。
4. 本地预设始终从SHA-256冻结的用户优化源重新生成。247个提示对象和214个排序条目不增不删；Doctor防全知模块仍位于最终输出协议之前，assistant prefill仍为最后一个启用条目。

## 必须新写及原因

- `recallSelectionInput()`是新的宿主适配胶水：成熟作品给出了“当前行动与历史分离”的合同，但不同项目的真实包装标签不同，不能原样复制其变量读取代码。
- `usage`消费证明是Doctor现有回执语义的缺口。Story Oracle证明的是指令注入/采纳，不拥有本医生的持久世界回执，所以只新写最小的必需项判定，没有引入第二套状态机。
- 本地预设构建器新写为确定性转换脚本，用源SHA、数量、改动ID、末位prefill和关闭项逐项失败关闭；预设文件本身不会上传仓库。

## 未复用与所有权边界

- 没有移植Story Oracle或2.0的完整规划器、租约状态机、UI或持久化层；它们与Kemini Clean现有世界权威状态和accepted-final回执所有权冲突。
- 没有让Doctor生成玩家动作、人格或正文，也没有让预设写Doctor私有世界。预设负责生成；MVU负责实时变量；数据库独立填表；Doctor只在正文后校验、补全人物、推进私有世界并持久化。
- Z论坛在本项目现有搜索范围没有找到可核对的兼容实现，因此没有以名称冒充复用。

## 验证边界

语法、JSON、构建、单元回归、差异和凭据扫描只证明候选可安装，不证明真实可用。0.6.15任何运行代码或提示词变化都会使0.6.14真实证据失效，必须更新扩展、导入本地配对预设并从一个全新聊天重新开始十二回合验收。
