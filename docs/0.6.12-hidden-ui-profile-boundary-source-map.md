# 0.6.12 隐藏 UI 与人物发现所有权根因修复来源映射

## 真实失败链

0.6.11 在真实全新聊天第 1 回合完成了变量官方重放、两张完整人物档案的原子写入/读回和世界修订 1 的提交/读回；Doctor 总耗时 115940ms，没有超过 120 秒。独立复核却发现人物模型被调用两次，其中一张档案的姓名或别名被隐藏 UI 摘要里的 `HTML内容简述：` 污染。

真实输入链为：Izumi 在 `</htmlcontent>` 后输出 `display:none` 的自然语言 UI 摘要 → Kemini 只丢弃部分面板容器，没有丢弃隐藏 `span` → `discoverProfileSubjects` 把任意冒号前文本当作说话标签 → 错误必建档锚点进入人物修复提示 → 第一次完整候选因无法覆盖假人物而被整批重试 → 第二次返回把展示层标题写进档案。医生报告“档案成功”只证明结构和读回完成，不能证明身份语义正确。

## 直接保留

- 人物模型必须通读完整最终叙事并主动补全正文没写死的档案字段。
- 每张新档案必须有清理后最终叙事逐字出现的稳定 name/alias。
- 同一张十四轴人物票据、候选合并、完整性门、整批原子 MVU 写入和读回验证。
- 变量医生、人物档案、数据库、世界引擎和预设各自的状态所有权与现有执行顺序。

## 最小适配

1. 现有栈式 HTML 清理器新增展示层判定：`htmlcontent`、布尔`hidden`、`aria-hidden=true`、`display:none`、`visibility:hidden`容器及其后代全部不进入人物观察文本。
2. 删除任意中文/英文“标签：内容”的脚本人物规则。脚本机械锚点仅保留`NPC-7`/`ACTOR-7`这类显式结构编号；普通姓名、代号和描述性称谓由人物模型从全文发现。
3. 模型候选继续只对同一份清理后正文做别名保留、身份逐字验真、证据补齐和首次出现排序；隐藏摘要即使含有人名也不能成为身份依据。

## 必须新写及原因

- Kemini 的输出直接进入扁平 JSON 档案流程，没有故事神域的可配置正文校正作用域，也没有旧医生的 ActorRef coverage-unit 事务。因此只新增一个兼容宿主 HTML 属性的隐藏容器判定，并嵌入现有清理器；直接复制任一完整解析器都会引入不属于 Kemini 的调度、状态和失败语义。

没有新增黑名单词条、第二人物识别器、第二状态机或第二持久层；正式仓库、预设、数据库与世界引擎不在本轮修改面。
