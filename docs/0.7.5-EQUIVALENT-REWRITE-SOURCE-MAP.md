# 0.7.5 “1+1=0+2”成熟主链等价改写来源映射

## 范围

本版本不在 0.7.4 的多重判断上继续加门禁，而是把变量、人物档案和世界推进分别收束回成熟作品已经验证过的一条主链。这里的“等价改写”指：保持成熟机制的输入职责、模型调用次数、输出用途、合并顺序和失败语义，用 Kemini Clean 当前接口重新表达；不是只借用名称后另造一套编排器。

用户本轮提供的跑团与 Doctor 报告只作为本地故障证据读取。附件正文、人物、变量快照、模型原始返回、文件路径与 API 信息均不进入仓库、测试夹具或本文，也未发送到外部模型。

## 三条等价主链

```text
变量：最终正文 + 玩家输入 + 全部活动规则 + 当前状态
  → 一次模型独立核对并输出必要修正
  → 官方 Mvu.parseMessage
  → 官方 Mvu.replaceMvuData
  → 一次目标读回

人物：最终正文 + 权威设定 + 世界观 + 已有档案 + 正文生成时真实票据回执
  → 一次完整档案填表
  → 宽容解析
  → 仅在必要时一次携带原候选和精确错误的定向格式修复
  → 整张档案一次原子提交与读回

世界：到期主体完整状态 + 最终正文 + 权威设定 + 当前只读MVU
  → 一次完整世界候选（尝试、裁决、代价、变化、下一步）
  → 一次稳定ID合并
  → 一次保存与读回
```

模型负责内容判断，脚本只负责提取、机械归一化、目标绑定、事务提交和恢复。脚本不得再增加另一轮自然语言裁判，反过来否决或删改模型已完成的语义内容。

## 直接复用、最小适配与必要新写

### 直接复用

- Story Oracle 的一次变量诊断调用，以及官方 `Mvu.parseMessage → Mvu.replaceMvuData` 应用顺序。
- 数据库/生理引擎的“一次完整填表；仅在机械格式仍失败时一次定向修复；整张原子提交”顺序。
- 旧世界引擎的“一次完整候选；一次合并；一次保存；失败恢复原状态”顺序。

这里的直接复用指控制流和失败语义保持一致；第三方源码没有整段复制进仓库，中文提示词和宿主调用点按本扩展接口等价改写。

### 最小适配

- Story Oracle 的“当前回复”在 Doctor 中钉住为 `chatId + messageId + swipeId + 正文指纹`，防止异步返回写到重 roll 后的新正文。
- 数据库的一行人物表映射为 Doctor 的一张完整人物档案；只读权威、正文硬事实、可修订推断和真实票据回执各自保留来源。
- 旧世界引擎的单一世界对象映射为稳定ID主体与变化历史；支线只是由真实变化派生的显示索引，不另存一套剧情真相。
- 世界模型读取当前 MVU 只作为事实，不能输出 MVU 补丁；数据库、预设、人物档案和世界状态继续拥有独立存储。

### 不得不新写的宿主胶水

- SillyTavern/TauriTavern 的聊天、楼层、swipe、正文指纹、重 roll 和新聊天隔离。
- Kemini Clean 的稳定 profile/subject ID、当前 `/人物档案` 根保护、chat metadata 保存、写后读回与最小事务日志。
- 运输失败、格式失败、内容不完整、目标陈旧和宿主保存失败的分类诊断，以及手动重试/撤销入口。
- 控制台对当前真实持久化结果的展示和刷新。

这些胶水只回答“写给谁、是否保存、怎样恢复”，不能回答“变量语义对不对、人物该知道什么、主体下一步该做什么”。后者只由各自主模型结合其权威输入完成一次。

## 明确删除的复杂机制

1. 把错误的当前 MVU 状态或原变量块当作正确基线，再让模型自证其正确。
2. 变量模型完成后再启动脚本自创的语义门禁或第二模型裁判。
3. 人物模型完成整张档案后，再用自然语言来源启发式删除知识、转移字段或令整张档案失败。
4. 正文生成阶段没有真实票据消费回执时，事后按叙事顺序给人物分配剩余票据。
5. 世界阶段先逐主体生成计划、再全局裁决、再逐主体生成下一计划的 `2N+1` 多轮请求。
6. 只发现名字就创建无目标、无变化、无下一步的“等待”主体，并把它计作活跃世界/支线。
7. 让一个格式错误使全部其他可解析主体、人物或变化回滚，或把空壳、空字段登记成成功。

## 所有权边界

- 预设：正文生成前的篇幅、视角、人物首次出场与正文创作约束。
- MVU：实时变量和官方更新解析。
- Doctor 变量阶段：正文后一次诊断、必要纠正、保存、读回、重试和撤销。
- Doctor 人物阶段：发现稳定 NPC、结合世界观补成完整档案并原子提交。
- Doctor 世界阶段：镜头外人物、势力、环境和社会过程的自主推进、私密记录与公开影响投影。
- 数据库：继续从最终接受正文独立填自己的表；Doctor 不读取数据库成功当作自己的写入，也不接管数据库状态。

## 验收边界

0.7.5 改变运行代码以及变量、人物、世界三个模型提示词，因此 0.7.4 和更早版本的所有真实回合、旧报告、旧构建与旧源码指纹均不能作为本版本证据。语法检查、JSON 解析、单元测试和合成回归只能证明候选具备进入真实测试的最低条件。

在当前 0.7.5 源码指纹完成真实 TauriTavern/SillyTavern 单一全新聊天连续十二个有效回合、且满足耗时和每回合独立复核要求之前，本版本只能标记为 Kemini Clean 测试候选；不得声称真实可用、正式发布或已经进入正式仓库 `main`。
