# 0.7.0 主体驱动世界核心来源映射

本文件冻结 `0.7.0` 的实现合同。它只描述来源、所有权与替换边界，不是正式酒馆验收报告。

## 中心目标

世界引擎不是支线续写器。它在最终正文被接受后，按人物、势力与自然/社会过程各自的性质、目标、有限知识、资源、阻力和时间条件，生成镜头外尝试并由世界条件结算为真实变化。支线只是这些变化按主题聚合出的阅读视图，不拥有第二份状态。

固定循环：

```text
选择本轮到期主体
→ 每个主体隔离读取自己的锚点、有限知识与上次结果
→ 独立生成并冻结主体本轮尝试
→ 本地票据锁定可行结果包络与公开渠道
→ 全局裁决只结合资源、阻力和时间结算冻结尝试
→ 每个主体再隔离读取自己的真实裁决并安排下一步
→ 局部合并真实状态变化
→ 现场派生支线与安全公开投影
→ 安排下一检查回合
```

每个接受回合都会运行调度，但不强迫所有主体在同一回合行动。时间不足时可以准备、观察或等待具体条件；笼统复述目标不算推进。

## 明确废止的旧合同

`docs/WORLD_ENGINE_V4_SOURCE_MAP.md` 记录的“删去调度字段”决定被废止；它让世界只有记录而没有稳定的自主调度。

以下结构不再作为 0.7.0 运行时状态或成功门禁：

- `threads` 作为权威状态；
- `lanes + attempts + adjudications` 三份相互链接的模型格式；
- `recall.pending / receipts / consumptionAnchors` 与逐字短语消费证明；
- 世界内部 `checkpoint / commitId / digest / prepared / committed / verified` 三阶段事务；
- 从 `fullRuns` 报告反向恢复权威世界；
- 任意缺字段导致整轮重试或整批失败；
- 一个主体缺失导致所有其他主体零写入；
- 由支线标题先决定剧情，再要求人物配合推进。
- 用同一内存对象冒充宿主刷新后的持久化读回；
- 对同一最终正文重复点击重试或复检时增加世界回合。

旧 schema 只允许在 `normalizeWorldState` 中一次性迁移为主体与变化；迁移后只写新 schema，不双写旧结构。

## 新权威状态

```text
world
├─ schemaVersion / chatId / turn / summary / updatedAt
├─ subjects[]
│  ├─ id / type(person|faction|process) / name / profileId
│  ├─ anchor / current / goal / knowledge[] / resources[] / constraints[]
│  ├─ observedFacts[] / nextAction / nextCheckTurn / status / silenceTurns
│  ├─ planReceipt（绑定主体、冻结attempt、ticket与真实裁决digest）
│  ├─ threadKeys[] / recentModes[]
│  └─ publicEffect / publicChannel / offeredTurn / shownTurn
├─ changes[]
│  ├─ id / subjectIds[] / threadKeys[] / turn
│  ├─ attempt / outcome / cost / stateChange
│  └─ visibility / publicEffect / publicChannel
├─ failures[]
├─ receipts[]（按最终回复sourceKey记录已推进与待重试主体）
└─ persistence(status / savedAt / readbackAt / error)
```

`branches` 由 `threadKeys` 聚合 `changes` 后现场派生，不持久化。人物、势力和过程共用同一变化合同，但过程主体依据条件、惯性和阈值演化，不能强行人格化。

## 模型偏向的本地票据

本地票据不是价值审查器，只限制无因极端化和无因媚玩家：

- `advanceMode`：行动、准备、观察、等待条件、改变计划；
- `intensity`：低、中、高，默认不允许凭空跨级；
- `resultEnvelope`：成功、部分、受阻、延迟，并要求具体代价或条件；
- `userRelation`：无关、可能交汇、已可观察；默认不围绕玩家；
- `publicChannel`：无、环境痕迹、传闻、具名公开行动、直接可见后果；
- `biasGuard`：禁止无因黑化/不可逆升级，也禁止无因信任、免费利益或主动服务玩家。

模型负责把票据和主体锚点具体化，不得改票据结果方向。同一 `sourceKey + turn + subjectId` 的票据确定不变；局部失败不会因为重试换结果。世界基调仍由角色卡、世界书和已接受事实决定，不能被本地票据统一成光明或黑暗风格。

模型请求按波次组织，不串行等待每个主体：已有可信 `planReceipt` 的普通回合是“全局裁决1波 + 各主体后续计划并行1波”；首次主体或旧存档迁移会多一波并行bootstrap。发现扫描只有1次全局请求。这是当前设计的性能上界；真实耗时仍必须由当前模型的十二回合酒馆门禁验证，自动测试不能代替。

## 所有权与提交边界

- 预设：正文生成前的篇幅、文风、视角、人物首次出场和玩家边界。
- MVU：当前实时变量；Doctor只修复结构和一致性。
- 数据库：独立填表及历史投影；Doctor不接管表格。
- 人物档案：Doctor结合最终正文、权威材料和同一张生成票据补全并持久化。
- 人物档案与世界人物主体：档案保存稳定身份、完整人格和可修订人物材料；世界主体保存会随回合改变的私密现状、资源、限制和下一步。旧档案快照只补世界空值，不能覆盖世界已落地的消耗与迁移。
- 世界：Doctor在最终正文接受后推进主体；同一最终正文只有一个 `sourceKey`，已成功主体不重复推进。保存调用成功后标记 `saved_unverified`，只有宿主后来重新载入当前聊天时才标记 `loaded`，不伪造即时读回。
- 正文注入：只注入安全公开影响；私密行动、动机、知识和未揭示结果留在 Doctor。
- 恢复顺序：同一最终回复的变量、人物和世界失败先按原票据恢复；失败仍存在时禁止开始下一正文。重 roll 则恢复该回复生成前快照，不把被舍弃 swipe 的Doctor结果注入新生成。

实现变化后，旧真实酒馆证据立即失效；正式可用结论必须重新完成当前指纹对应的真实酒馆协议。
