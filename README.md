# MVU 人物与世界医生（Kemini Clean）

## 0.7.2 数据库式档案补全、生成前票据消费与玩家硬事实

- 人物阶段改成成熟数据库填表分工：最终正文、角色卡、世界书、已有档案与骰票只负责锁定不能冲突的硬事实；正文没有写出的外貌细节、日常习惯、背景经历、表达方式、欲望和弱点由人物模型主动补成完整档案，并统一标记为后续可修订推断，不再把两千字正文当作档案信息上限。
- 普通知识缺少人物可达来源时，只从 `knowledge` 下沉到 `inferences`，不再因一句越权知识否决其余完整字段；系统、数据库与权限读取等特权知识只信既有持久档案、角色卡/世界书实际条目或同人物正文明确显示的身份和访问权，并要求具体事实能与这些可信材料核对，模型候选不能靠自写身份或能力给自己授权。每张档案仍必须整体完整、原子提交并读回，不能用空字段制造通过。
- 正文生成前新增 `CharacterTicketReceipt`：每个实际出场的稳定 NPC 优先记录为 `ticket`、`authority` 或 `existing`。有效映射只绑定其中已经消费的那张票，权威身份仍须由真实角色卡/世界书材料证明；回执漏写、损坏或漏人时不再卡死建档，而是原子保存一张标明来源状态的完整无票档案，绝不在正文后从剩余票据池任配。
- 人物内容或格式暂时失败时保留候选和定向重试，但不再冻结已有的人物、势力、环境与任务主体；下一回合成功也不会静默清掉旧漏档任务。稍后手动补档时仍以原楼层正文和骰票作证据，只把完整人物根合入当前最新MVU并同步继承该证据的swipe快照，不重放旧变量或旧世界。只有人物身份冲突、写入失败、读回不一致或目标变化这类真实事务故障才阻断相关消费者。
- 变量提示明确把玩家本回合填写的姓名、身份、点数和资源分配置于助手自创内容之上，并禁止把 NPC 的引导、邀请或要求当成玩家已经照做。规则同一行明确标记“禁止修改/只读/read-only”的路径，或嵌套 Schema 中由纯容器键向下连接到同一明确标记的路径标题，会被脚本确定性剔除；普通自由文本和同级其他路径不参与推断。脚本还会删除经官方 MVU 重放证明“移除后最终状态完全相同”的冗余操作。
- “复制诊断”继续脱敏；“导出完整报告（除API）”改为只排除真实 API 配置、授权头和当前连接凭据。剧情与变量中恰好名为 `secret`、`token`、`headers` 或 `credentials` 的字段和原文不再被诊断脱敏器误删。
- 本地配对的 Izumi 0825 私有预设保留全部 247 个提示对象和 214 个顺序项，只在原有输出/思维条目中追加玩家行动 A 锁与票据消费回执。预设不进入仓库。

完整复用边界见 `docs/0.7.2-DATABASE-STYLE-PROFILE-TICKET-AGENCY-SOURCE-MAP.md`。本版本改变运行代码、人物与变量提示词以及本地配对预设，所有旧真实回合证据均已失效；完成当前源码的真实酒馆十二回合门禁前仍是测试候选，自动测试不能证明正式可用。

## 0.7.1 成熟变量医生、人物可达知识与响应式控制台

- 变量医生回到故事神谕与旧 Doctor 已验证的单任务结构：`当前活动规则 + Schema/初始化 + 触发用户输入 + 最终接受正文 + 上一楼层基线 + 当前 stat_data + 最近对话 → 一次聚焦模型判断 → 一个本回合完整 UpdateVariable`。它从上一楼层重放，保留正确原更新、删除错误更新并补齐遗漏；不再把“原 delta + 二次纠错”叠加成刷新后可能重复执行的块。
- 删除脚本自创的键值收据、风险检查表、baseline 空补丁门、规则文本正则裁决、坏块终态反推和“拒绝一部分再提交剩余部分”的状态机。宽容解析先恢复围栏、缺失外壳、唯一平衡数组和常见 JSON 机械错误；仍失败时，第二次模型调用必须携带首次原文与精确错误，只修格式、路径或类型，不重新审剧情。
- 保留成熟安全壳：聊天/楼层/swipe/正文身份钉住、官方 `Mvu.parseMessage` 从重放基线干运行、`/人物档案` 根从最新状态原样带入、按官方实际差异建立写前日志、`replaceMvuData` 后读回、派生路径一并回滚和手动撤销。正文只做唯一块替换；边界多义时零写入，不再把数据库或其他扩展的同回合变化吸进坏块。
- 空补丁只记为 `model_reported_nochange`，UI 明示“模型本次没有提出修复，不等于脚本证明变量无误”。手动复检可填写具体疑点，仍复用同一提示词与安全写入链，不会串行触发人物或世界。
- 变量正文保存、结构修复和撤销后统一按 `updateMessageBlock → MESSAGE_UPDATED` 刷新；接口缺失或事件失败不回滚已确认数据，但会留下黄色诊断和手动刷新提示，不再静默宣称面板已更新。
- 宿主真实激活条目优先；选中/绑定世界书只额外读取启用的常驻条目、明确 `[mvu_update]` 与初始化条目，角色卡内嵌书仅作回退。预设、MVU、Doctor 人物档案、Doctor 私有世界和数据库继续各自拥有自己的状态；MVU事务未闭合时世界引擎不会消费未确认状态。
- 人物知识允许有身份、能力、资源或正文证据支持的系统授权读取；普通人物不能借“系统得知”获得全知。
- 控制台用视口约束替换旧固定尺寸：桌面上限 960×900，主内容是唯一滚动区；顶部实时栏只保留有界摘要，完整详情仍在可滚动的“当前结论/诊断”中。手机、粗指针平板和横屏使用动态可视视口、四侧安全区、44px 触控目标、页面滚动锁、焦点圈定和短高度布局。

## 0.7.0 人物与主体驱动的世界后台

- 世界状态现在只有一份权威：`subjects + changes`。人物、势力与环境/社会过程是会行动或演化的主体；“支线”只从真实变化中派生为阅读索引，不再保存第二套会漂移的剧情真相。
- 每个接受回合都运行本地调度器，但只选择到期主体。每个主体先在物理隔离的请求中，只根据自己的性质、目标、有限知识、资源、阻力和可达公开信息决定尝试；脚本再锁定方式、强度、结果方向、与玩家的关系和公开渠道。全局裁决只能逐字结算这些已冻结尝试，看不到也不能写入各主体的目标、知识、下一步和检查回合；人物意愿不会直接变成世界成功。
- 主体计划与世界裁决都用可读的自然语言分块。单个坏块只跳过对应主体，其他合法块照常合入；失败主体保留同一回合、同一张本地裁决票并只重试自身，成功主体不会被再次推进。后续计划还会绑定它真正依据的裁决摘要，重试结果变化时不复用旧计划。成功、部分成功、受阻和延迟都必须留下真实状态变化、成本或具体再检查条件。
- 人物档案改为逐人隔离、整张原子提交：一张坏档案不再拖死同轮所有完整档案；未达标人物保留为定向重试，经过变量提交屏障后仍以完整候选集合复核。局部重试会先占用已提交人物的票据与ID，不能抢票覆盖成功档案。既有档案按字段所有权合并：稳定身份、原票与十四轴人格默认冻结，事实型列表累积，动态字段只有本回合正文中同一人物可核对的变化才能更新。MVU、Doctor 档案和数据库仍各自独立。
- 每条 accepted 正文先运行一次独立、短格式的人物发现：只接受正文逐字姓名或唯一称谓及其逐字锚点，也允许明确 `NONE`。发现回执与原有机械候选、票据和恢复对象合并后，才交给完整档案模型；发现运输或格式不可恢复时进入人物定向重试，不能用一次 `<人物档案无变化/>` 把普通具名 NPC 静默漏掉，也不创建只有名字的空壳。
- 人物身份冻结不再靠“任意共享别名”或“模型自填票号”相似匹配：只认精确 `profileId`、当前批次唯一有效票号或唯一主名。未提交的重复票号按正文首次出场顺序重分；世界书权威人物只认结构化且唯一的精确标识，不再因条目正文偶然包含名字就抢走原创档案。
- 正文只接收安全公开影响。后台私密现状、伪装、真实动机、镜头外步骤和完整因果不会注入正文；环境痕迹、未证实传闻、具名行动和直接后果分别接受本地渠道校验。提供不等于已呈现：最终正文没有采用的影响只进入短冷却，之后仍可召回。
- 旧档案如果没有经正文确认的 `narrativeKnownNames`，正文摘要只给不透明句柄，不回退注入真名或全部别名。同名世界主体也必须用稳定ID指定，不容许模型用名字猜测要改哪一个。
- 世界页直接显示主体、最近变化、派生支线和局部失败；独立复检入口对同一最终正文执行幂等核对，不会多推进一个世界回合。提交后只诚实显示“已请求宿主保存”；只有刷新或重新载入当前聊天后才显示宿主读回，诊断报告不会参与状态恢复。
- 重 roll 只有在命中同楼层生成前检查点时才恢复并重新结算；旧聊天没有检查点时保留新正文，但隔离本次 MVU 修复、人物档案和世界写入，避免旧 swipe 反向污染。
- 普通下一回合开始前会先自动恢复上一条最终回复的失败步骤；仍失败时由 SillyTavern 的 `generate_interceptor` 在真正发送主模型请求前取消本次生成，防止历史人物/世界结果在新回合之后倒序落地。重 roll 仍走生成前快照，不执行这条普通续写恢复链。
- 生成请求发出前会先保存 `generating` 恢复票；`GENERATION_ENDED` 后更新为 `ended`，并在500ms fresh-read到精确聊天、楼层、swipe与正文指纹后才开始Doctor。刷新/崩溃会从该票续跑；宿主明确停止且正文未接受时会撤销该票，不把取消生成变成幽灵回合。
- 重 roll 在改写任何Doctor权威之前，先把当前swipe的MVU人物根、Doctor档案、世界、重试与票据保存为写前日志。中断后只能向完全一致的原swipe恢复，身份分叉就隔离，不跨聊天覆盖。
- 新 overswipe 只按宿主的真实槽位形态识别：`swipe_id === swipes.length` 且目标槽尚未成为字符串；合法的空字符串历史 swipe 仍是既有结果。交接只使用一份 `preparedReroll` 写前日志并严格绑定紧邻的 `target-1` 来源，停止或刷新会先把宿主可见 swipe 持久切回来源，再恢复 Doctor 权威并清票，不能向前扫描或把同文新 swipe 当成旧结果。
- accepted-final 使用单一持久生命周期：主请求前写入 `generating`，`GENERATION_ENDED` 后变为 `ended`，等待至少 500ms 并精确读回聊天、楼层、swipe 与正文指纹后才写入 `accepted`；Doctor 只消费 `accepted`。禁用扩展不会偷偷消费任何恢复票据，主请求释放前的取消会撤回本次准备和重 roll 基线。
- 最终正文对既有主体造成的逐字事实会独立写入 `observedFacts` 和变化历史，不覆盖主体的私密现状、资源与下一步，也不自动升级成人物知识；主体到期后再按自身可达信息调和。
- 配对的本地 Izumi 0825 最新预设完整保留原条目，只新增一个可关闭的 `MVUDoctorRuntime` 接收模块；预设仍不进入仓库。实现来源与取舍见 `docs/0.7.0-SUBJECT-DRIVEN-WORLD-SOURCE-MAP.md`。

## 0.6.20 世界裁决必须产生真实状态变化

- 世界模型不能再用一段 `resultSummary` 把没有任何落地变化的尝试写成 `success/partial`。这两种终态必须有非空、可读的 `appliedStateChanges`；行动还必须给出预计耗时与风险，裁决必须给出实际耗时。
- 生产验证在世界事务准备与持久化之前失败关闭；`applyWorldProposal` 也增加同一终态下限，绕过上层验证的坏候选只能留下 `pending_world`，不能写入成功裁决或把对应尝试标成 `settled`。
- 防全知边界没有被反向削弱：隐秘行动可以没有当前公开表象，但必须同时拥有真实私密状态变化和未来发现路径；这类私密变化不会因为“裁决完整”就自动注入正文。公开行动的成功/部分成功则必须有安全的可观察后果。
- 配对的本地 Izumi 0825 预设内容不变，继续使用 0.6.19 的完整保留适配文件；数据库、MVU、Doctor 私有世界与预设仍分别拥有自己的数据。完整来源映射见 `docs/0.6.20-WORLD-ADJUDICATION-SEMANTIC-SETTLEMENT-SOURCE-MAP.md`。

## 0.6.19 并行候选、召回锚点与玩家认知边界

- accepted-final 后变量审计与人物候选生成并行启动；变量通过并读回后，世界候选与仍在运行的人物候选继续并行。提交顺序仍严格保持“变量验证 → 人物原子提交与读回 → 世界事务提交”，失败依赖不会留下半张档案或迟到世界写入。

- 召回回执不再用相似二元词组推断“正文已经消费”。公开投影生成确定性 `consumptionAnchors`，只有最终正文逐字包含公开锚点（或旧包的完整公开片段）才结算；模糊近义复述一律释放，不能再制造假阳性回执。

## 0.6.18 世界公开投影局部修复与取消主权

- 严格 JSON 先原样解析；只有确实解析失败才进入宽容修复，合法字符串里的中文引号不会再被修复器反向破坏。
- 宽容修复改为字符串边界感知，只处理字符串外部的注释、裸键、单引号结构、缺逗号和尾逗号。
- 每次人物修复保留并合并上一轮最佳候选，只把缺失字段和错误类型交给下一次修复，不再整张推倒重做。
- 可确定的列表类型由代码归一化；正文证据只从最终叙事区提取，不把思考链、变量块或未执行选项冒充已经发生的事实。
- 医生耗时从 `accepted-final` 开始计算；完整报告另存总生成链耗时，正文生成等待不再算进医生耗时。

## 0.3.0 前端与基础功能

本版前端从零编写，没有复制旧医生的 HTML、CSS、组件或任务控制结构。旧版资料只用于确认用户需要哪些入口。

- 总览：本轮阶段、普通中文状态、档案/世界项数量、票据数、召回上限、修复次数、取消与失败步骤重试。
- 连接：继承酒馆当前模型或使用独立 OpenAI-compatible API；支持地址、可选密钥、模型、模型列表获取、真实响应测试、人物/世界输出上限，以及唯一的全局模型适配附加提示词入口。
- 人物：按姓名选择并查看身份、外观、生理、十四轴人格、经历、当前状态、关系、知识、能力、资源、正文证据与可修订推断。
- 世界：查看世界摘要、支线、NPC 行动倾向、约定与敌对计划；NPC intent 始终标为倾向/尝试，不冒充世界裁决成功。
- 诊断：保存当前聊天最近 30 条脱敏记录与最近 6 次完整运行记录，显示失败影响和“怎么解决”，支持复制脱敏诊断、清空诊断、安全重试同一最终正文的失败步骤，以及“导出完整报告（除API）”。完整报告含私人正文及尚未归档的当前运行会话，不能公开上传；API 连接和凭据仍会被移除。
- 移动端：窄屏使用全屏控制台，桌面使用右侧大面板；所有正文、人物与世界数据都以 `textContent` 渲染，不把模型内容作为 HTML 执行。

自定义 API 密钥保存在 SillyTavern 的医生扩展设置中，不写入聊天 metadata、诊断记录或仓库。若所用端点不允许 WebView 直连，可改用“继承酒馆当前模型”；本候选尚未实现旧医生的后端代理、多连接预设和多槽位路由。

## 明确边界

- 数据库：扩展不读取、不写入、不声称代表数据库成功。
- 预设：不上传到本仓库；本地适配版以用户优化最新版为唯一母版，保留原 242 个 prompt、209 个顺序项、原有参数和正则，只把重复启用的人物适配补丁收束为一个统一入口。
- 医生：正文后依次处理 MVU 变量检查/修复、人物档案和世界连续性；人物首次出场的人格随机仍由生成前脚本票据决定。
- 世界引擎：记录 NPC 的计划或尝试，不把未裁决尝试伪造成成功结果。
- 玩家自主权：脚本和追加提示均禁止替玩家决定行动、感受、同意、关系或结果。
