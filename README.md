# MVU 人物与世界医生（Kemini Clean）

## 0.6.11 人物发现与世界公开投影误重试根因修复

- 人物脚本不再用“任意中文片段 + 动作词”的自由散文正则冒充人物识别；它只固定显式说话标签和稳定 ID 这种高置信下限，完整正文仍由人物档案模型审阅。
- 每张新档案必须有最终叙事逐字出现的稳定 name/alias；代词动作片段、连接词和机制字段即使字面出现也不能成为人物身份或别名。
- 世界公开投影不再因裸“秘密”二字误判。公开言行可以如实保留；秘密身份、目的、计划、行动和记录等未公开内容断言仍会被拒绝。
- 保留变量先确认、人物后补全、世界再推进的现有顺序，没有引入并行状态机，也没有删除档案字段、世界记录或重试恢复。

> 0.6.11来自0.6.10同一真实聊天的三回合独立耗时审计：前两回合的人物阶段分别因假人物锚点整次重跑，第三回合的世界阶段因词面误杀整次重跑，最终在第二次 Doctor 超过120秒时按硬门停止。自动检查只证明新候选可重新进入全新聊天验收；不代表真实门禁已经通过。

## 0.6.10 真实MVU重放基线与空补丁证据门

- 原正文变量块不再由Doctor自行按JSONPatch字面值模拟后判定是否落地；Doctor会在上一楼层数据副本上两次调用官方`Mvu.parseMessage`，只有两次结果确定一致且与当前真实`stat_data`一致时，才确认原更新已经落地。公式、Schema归一化与`VARIABLE_UPDATE_ENDED`监听器产生的合法衍生值因此不会再被误报。
- 重放缺失、抛错、两次结果不一致或与当前状态不同都会失败关闭，不会把静态模拟结果冒充宿主证据；重放只作用于内存副本，不写变量，也不重放原`delta`。
- 模型返回空补丁时必须引用至少一个真实JSON Pointer路径，并写清该路径的正文事实与前后值对照；复述提示词模板、“逐项核对后无需修复”或只说“差异为0”会重试并在耗尽后零写入失败。

> 0.6.10来自0.6.9真实首回合的独立复核：正文31个原操作已由真实MVU全部处理，当前完整`stat_data`与官方重放逐字段一致；旧静态基线却把前端自动计算后的MP、防御、闪避和负重上限与原字面值比较，错误阻断了人物与世界。自动检查只证明候选具备进入全新聊天真实验收的条件。

## 0.6.9 处理中状态优先于阶段完成措辞

- 人物档案已提交但世界仍在处理时，外层状态继续显示“医生处理中”，取消与手动入口也继续按忙碌态保护；只有变量、档案、世界与召回都离开`pending/ready/running`后才允许显示“医生已就绪”。
- 该行为最小适配自成熟五色健康投影的“后台运行强制蓝色busy、错误再覆盖busy”机制；不新建并行状态机，继续使用现有`runtime.progress`作为阶段所有权来源。

> 0.6.9来自0.6.8真实首回合：人物档案已原子提交后，世界仍在运行，但外层一度提前显示“医生已就绪”。同轮还暴露了配对预设替玩家断言感受与想法的问题，预设修复与本版本配对后必须从全新聊天重新验收。

## 0.6.8 对称正文结构修复与失败态纠正

- accepted正文恰好只有一个`</content>`、且首个`<check>`或`<story_body>`与后续`<options>/<UpdateVariable>`共同给出唯一边界时，Doctor会在首个正文锚点前补入`<content>`并持久化后再继续；自由文本无锚点、无后续边界或多标签仍然零写入拒绝，不猜正文起点。
- 明确的正文结构失败不再被通用诊断文案降级为蓝色busy：主状态为红色错误，召回显示已释放，MVU、人物和世界显示未开始。

> 0.6.8来自0.6.7真实首回合：预设输出0个content开标签、1个闭标签；0.6.7已正确释放召回且拒绝下游隐藏生成，但结构修复缺少对称分支，失败状态也被错误映射为busy。当前变化要求全新聊天重新验收。

## 0.6.7 主正文生成身份门与单容器预设配对

- Doctor只在“新用户消息已进入聊天、输入框仍有待发送内容、continue或reroll”之一得到真实证据时接收`GENERATION_STARTED`；全局停止控件不再被误当作正文身份，accepted正文后的数据库或其他下游隐藏生成事件不再新建Doctor会话、重复注入或让面板假忙。
- 配对的本地0825适配预设将多次检定、状态栏和HTML/UI明确收进唯一一组`<content>...</content>`，并增加发送前单容器计数门；不改Izumi原有核心提示词，只调整隔离的轻量输出/思维链适配模块。

> 0.6.7来自0.6.6真实首回合的两条独立证据：双`content`被正确零写入拦截；随后下游隐藏生成事件被旧监听误认成新正文并使面板假忙。任何源码或预设变化都要求全新聊天重测。

## 0.6.6 accepted-final结构修复与人物档案语义门

- 最终正文恰好缺少一个`</content>`且后面存在明确`<options>`或`<UpdateVariable>`边界时，医生会在任何变量、人物或世界处理前确定性补回并持久化；多标签、空正文或无明确边界仍然零写入失败，不猜结构。
- “未知（外观为青年）”“待定（以后确认）”等占位词包装不再通过完整性门；人物档案必须给出可用年龄或年龄段。
- 新人物别名只接受脚本从最终正文提取的逐字人物锚点；既有人物继续保留已持久别名。代词、动作截断和句子碎片会在原子提交前移除，并留下归一化记录。

> 0.6.6 修复来自0.6.5真实首回合的独立复核；自动测试通过只代表候选可进入新的真实酒馆验收，不代表已经可正式使用。

## 0.6.5 结构等价读回与键顺序无关验证

- 变量干运行、提交前状态漂移、写后读回、路径快照、人物档案提交和reroll检查点统一使用JSON结构深比较：对象键顺序不再影响结果，数组顺序仍严格保留。
- 修复真实MVU会规范化动态对象字段顺序时，Doctor把完整落地的背包物品误报成“目标路径未按预期落地”并阻断人物与世界的问题。
- 这不是放宽字段或跳过读回；字段缺失、值变化、数组顺序变化以及补丁外路径变化仍会失败关闭。

> 0.6.5 的真实失败只读复演已证明字段和值完整，仅对象键顺序不同；任何运行代码变化都会使旧真实证据失效，因此必须从全新聊天重新验收。

## 0.6.4 人物发现边界与正文面板隔离

- 人物发现器先剥离正文中的HTML状态卡、属性面板和其他展示组件，再识别真实说话或行动的参与者。
- `HP/STR/名称/品质/属性加成`等面板字段、全大写统计缩写及“继续/这番/便可将其”等语法碎片不再被当成人物。
- “引导者微微点头”“白露微笑着”等句式会在动作词边界处正确保留人物名，不再制造“引导者微”一类半截身份。
- 保留稳定英文姓名、NPC编号、角色称谓及现有完整档案的覆盖逻辑；仍不从规划、选项、变量块或医生私有内容建档。

> 0.6.4 的自动回归和旧失败回合只读复算已经通过；任何运行代码变化都会使旧真实证据失效，因此必须从全新聊天重新验收。

## 0.6.3 变量字段所有权与真实MVU拒绝项分离

- 变量医生先读取角色卡的实际更新规则，拒绝模型写入脚本托管、前端自动计算或明确禁止修改的字段。
- 背包是否计入负重不再由通用提示词猜测；系统空间与未装备物品只按角色卡自身规则处理。
- 同批纠错中若真实MVU只拒绝部分路径，拒绝项会被分离，能够真实落地的修复仍继续原子提交和读回。
- 正文原更新已经真实落地时，被角色卡或真实MVU拒绝的模型建议会以明确诊断零写入收束，不再阻断人物档案与世界引擎。
- Doctor生成的变量块改为与无限回廊现用结构一致的分行标签格式；格式只是兼容收敛，字段所有权才是本次根因修复。

> 0.6.3 在真实首回合修复了变量误判，但人物发现器把HTML面板字段误认成人物，故已由0.6.4替代，不能作为可用证据。

## 0.6.2 人物覆盖、召回实消费与面板同步

- 人物阶段不再把模型的“无变化”当作独立复核。脚本先从最终接受正文中保守提取实际说话、行动的稳定姓名、编号和唯一称谓，再要求完整档案的 `name` 或 `aliases` 逐一覆盖；锚点非空时，模型返回“无变化”会被拒绝并定向补全。
- 人物锚点只用于确认“谁必须有档案”，不从正文自由推断档案内容；角色卡主体、玩家、已持久人物、群体、结构标题、计划区和选项均被排除。档案仍按同一张人物骰票补全、整批校验、单根原子写入和读回。
- 世界召回不再在正文结束时无条件记成“已消费”。相关性也只在防全知裁剪后的公开投影上计算，不读取私密摘要来决定注入、不拿无关项凑满上限；正文有可核对采用痕迹才记录“正文已采用”，否则记录“正文未采用”，完整原因进入回执与运行报告。
- 人物档案写入读回后立即刷新人物页，不再等待世界模型结束；世界提交仍先立即重绘，最终完成流程再等待一次当前聊天的世界、诊断和人物读回，避免报告成功而面板停留旧状态。
- 本版本继续保留 0.6.1 的变量本地基线、Schema/MVU 干运行、事务写入、读回与回滚链；数据库、预设、医生档案和世界状态的所有权没有合并。

> 0.6.2 已通过当时源码的构建、语法与 65 项自动回归，但真实首回合暴露了变量字段所有权根因，因此不构成可用证据。

## 0.6.0 私有世界与防全知投影

- 世界状态升级为 v5：`summary / offscreenBeat / nextBeat / actorActions / resultSummary` 属于医生私有层，允许真实记录并推进 NPC 的隐秘目标、伪装真相、镜头外行动和世界裁决。
- 正文预注入不再序列化完整支线和行动。脚本只生成公开投影：当前可观察表象、无因果归属的线索、明确存在的传闻、已经由最终正文证据揭示的事实，以及公开行动的可观察后果。
- `hidden` 不再只是标签。没有公开表象或后果的私有事项不会进入召回；隐藏行动的行动者、目标、具体尝试、成败、成本、私有下一步和发现路径不会被送给正文模型。
- `knowledge=observed` 必须附带本轮最终正文中的精确 `revealEvidence`，防止世界模型自行把秘密标成“玩家已经知道”。公开字段出现“其实、暗中、无人察觉、真实目的、伪装”等典型全知叙述会被拒绝并定向重试。
- 人物档案拆成两类摘要：正文只收到哈希身份句柄、脚本曾在最终接受正文中逐字确认过的公开称呼，以及“不得重新随机”标记；原始profileId、未公开真名、职业、人格、当前目标、知识、资源和医生推断只提供给人物修复与世界引擎，不再反向泄漏。
- 世界页继续显示完整私有状态，且明确区分“正文可见表象/线索”与“医生私有摘要/推进”。完整报告仍保留全部私有世界内容并排除 API 连接和凭据。
- v4 统一世界状态会原样迁移到 v5；迁移不再把“版本不同”误判成旧四数组，从而丢失已有 threads。

> 本次改变运行提示词和世界召回语义，旧真实酒馆证据已经失效。当前硬门仍锁定“无限回廊5.9 + 99条内嵌世界书”，与本次 7.0.2 跑团材料不是同一验收对象；完成匹配环境下的十二轮真实验收前，本版本只能称为本地候选。

## 0.5.0 变量审计与修复事务重写

- 本次变量链完全依据功能目标重新编写，没有打开、复制或移植旧医生代码。旧实现只留下“正文后检查、失败可恢复、结果必须读回”的需求结论，不作为代码来源。
- “无需修改”不再凭模型一句空补丁成立：每次必须回显本轮审计编号，并逐项提交初始化、数值与派生值、装备转移、动态集合、关系与精神因果、时空成本、玩家自主权的证据回执；高风险项必须引用真实存在的当前状态路径。
- Schema拒绝、MVU干运行不闭合、补丁外路径变化、提交前状态漂移、写入读回不一致现在都按变量阶段失败处理；人物档案和世界引擎不会越过失败继续运行。
- 每次修复先保存 `prepared` 事务和触碰路径快照，再写MVU、读回、合并正文并持久化。失败只回滚该事务触碰路径；刷新后会恢复或隔离中断事务，不用整份旧状态覆盖并发变化。
- 总览与诊断页新增独立的“重新检查当前MVU变量”和“撤销上次变量修复”。手动复检只运行变量阶段，不会顺带重跑人物或世界；撤销前会同时核对当前补丁与路径快照。
- 完整运行记录由6次提高到24次，并至少保留12次；完整报告同时包含变量审计回执、补丁、事务状态与路径快照，仍排除API连接和凭据。

- 兼容 TauriTavern 在用户消息写入聊天数组之前触发 `GENERATION_STARTED` 的真实时序：此时按“当前消息数 + 1”绑定即将生成的助手楼层，并直接读取尚在输入框中的本轮文本用于召回。

> 测试候选版：尚未执行真实 TauriTavern / SillyTavern 十二回合验收，不能视为正式发布或“已经可用”的证明。本仓库供用户自行安装实测。

当前版本：`0.6.11`。运行时核心已经打包进 `index.js`，不依赖 `document.currentScript` 或额外定位 `core.mjs`，兼容以非脚本标签方式执行扩展入口的酒馆加载器。

- 新聊天或聊天载入完成后，医生会先恢复当前作用域的事务与世界检查点，再把前端状态明确闭合为“医生已就绪”；旧聊天的取消提示不再长期显示成 busy。

这是一个轻量医生扩展。前端、控制台与本版变量事务链均独立编写，不复制旧医生 UI 或代码；可与本地交付的 **人物万花筒用户优化最新版 MVU 人物世界适配预设** 配合完成完整链路：

1. `GENERATION_STARTED` 时先掷出十四轴 `characterCreationTicket`，同时从医生私有世界状态筛选与本轮输入相关的支线和 NPC 倾向。
2. 票据和经过防全知裁剪的公开召回投影在正文生成前注入；用户优化最新版的原有正文、篇幅、选项和 MVU 提示词继续负责正文。私有真相仍留在医生世界状态中。
3. `GENERATION_ENDED` 后等待 500ms，先让变量医生把当前 `stat_data` 当作“原变量块已经落地后的状态”审计，只提交纠错，避免重复执行原 `delta`；补丁必须通过本卡 MVU/Schema 解析、写入、读回，失败回滚。
4. 变量终态确认后才检查人物。预设的 `<人物档案无变化/>` 只是候选结论，医生会独立复核稳定姓名、编号和唯一称谓 NPC（包括“引导者”一类角色）。
5. 全批档案先解析、补齐票据、校验；任一档案不完整则零写入。完整批次一次投影到 `/人物档案/byActorId` 并读回，同时保存医生自有恢复副本，不接管数据库。
6. 档案完成后，才按“继承酒馆当前模型”或用户填写的独立 OpenAI-compatible API 推进统一世界状态；同时处理连续性支线、人物自主行动、阵营和环境，但严格区分“行动尝试”与“世界裁决”。
7. 世界候选先写入准备检查点，随后提交，并用修订号、提交号和摘要做保存后读回；任何一步不一致都不会显示为成功。
8. 下一回合按玩家输入、人物、地点和关键词生成一次性召回包；最终正文确实采用公开投影时才记录已消费，否则明确释放并记录未采用原因。
9. 诊断页可导出不脱敏完整报告，包含聊天、变量、提示、原始模型返回、人物和世界记录，只排除 API 连接与凭据。

预设文件受本项目隐私边界保护，不在本仓库、不在任何提交历史中，也不会由扩展联网下载。用户需要单独从本地导入适配预设。

## 安装与自测

1. 在 SillyTavern 扩展安装器中使用本仓库地址安装扩展。
2. 从本地导入单独交付的 `01_主预设_人物万花筒_可调篇幅_IZUMI0825作者完整保留_原作高还原_Aether破限_NPC自主增强_MVU医生防全知适配版.json`。
3. 保持 MagVarUpdate / MVU 正常启用；数据库、世界书和缝合怪仍按自己的方式独立工作。
4. 点击右下角“医生”按钮，或在扩展设置中点击“打开医生控制台”。
5. “连接”页可选择继承酒馆当前模型，或填写独立 OpenAI-compatible API 地址、密钥和模型，并执行真实连接测试。
6. 新建聊天测试。“人物”页读取当前楼层 `/人物档案/byActorId`；“世界”页显示连续性支线、人物行动与世界裁决、阵营、环境、解决历史和持久化读回证明。
7. 若显示“人物档案失败”，本轮不会把半张档案算成功；“诊断”页会显示普通中文问题、解决办法和安全的失败步骤重试入口。

建议测试至少覆盖：没有新人物、一个新人物、同轮多名新人物、旧人物再次出现、切换聊天、停止生成、刷新后读回、世界引擎失败后下一轮恢复。

## 0.4.0 世界连续性根因重构

- 修复旧版异步根因：`metadata()` 不再每次读取都重建并替换整个医生命名空间；长模型请求结束后只在最新权威对象上提交，避免“报告有新结果、实际存档和面板仍是旧状态”。
- 废止四数组作为运行时权威结构。旧 `branches / npcIntents / agreements / hostilePlans` 只做一次迁移，并可从同一聊天最近完整运行记录恢复 0.3.4 曾生成但没有真正落盘的更多世界项。
- 新世界状态使用 revision、commitId、digest、observedThrough、simulatedThrough 和 SourceRef；模型输出先成为候选，再经准备检查点、提交和保存后读回。
- 连续性按人物、阵营和环境通道推进。模型漏写旧项不会把旧支线删除；明确解决的支线进入历史档案。
- 人物自主行动分成 `ActionAttempt` 与 `WorldAdjudicationResult`。未建成完整档案的人物不能越权自主行动，但结构性世界支线仍可继续。
- 世界提示现在同时读取最终接受正文、医生持久世界、行动就绪人物摘要和当前 MVU 只读事实；医生仍不接管 MVU 或数据库写入。
- 世界页重新组织为连续性、人物尝试/裁决、阵营、环境、解决历史和持久化证明；刷新读取始终以当前聊天权威存档为准。
- 下一回合召回具有 packageId、世界版本和 consumed/released 回执，只服务一次正文生成。

## 0.3.4 报告导出与世界面板同步

- 世界状态提交并保存后立即重绘世界页和状态计数，不再等待人物 MVU 的异步读回；即使 MVU 读取失败，已成功保存的世界推进也会显示。
- 完整报告在用户点击按钮时先申请本地保存位置，避免异步收集完成后浏览器丢失下载授权；不支持文件选择器的宿主仍使用下载链接回退。
- 当前楼层 MVU 读取失败时不再取消整份报告，而是在报告内记录该段读取错误，并继续导出聊天、医生运行、人物恢复副本与世界状态。
- 报告清理器可安全处理循环引用、BigInt、日期、Map、Set、TypedArray 和 Error，同时继续排除 API 字段及实际凭据。

## 0.3.3 诊断终态根因修复

- 诊断卡现在首先读取明确的运行阶段码，而不是在详情文字里搜索“世界、变量、支线”等关键词。
- `completed` 记录中的“世界项N条”不会再被误报成“世界支线没有完成”；已有聊天刷新诊断页后也会按保存的真实阶段码重新显示。
- `variable_failed`、`profile_failed`、`world_failed` 仍分别显示对应失败及恢复入口，未知旧记录才使用兼容性关键词判断。
- 新人物结果自创ID或漏写票据号时，脚本按最终正文的首次出现顺序绑定本轮既定骰票；这是可确定的格式归一化。若还有真实内容缺项，下一轮只报告并补这些缺项，不再先浪费一轮处理ID格式。

## 0.3.2 人物档案主动补全

- 最终正文只用来确认哪些人物实际出现、哪些硬事实不可违背，不再被当作档案信息上限；正文没写全时，医生必须根据角色卡、相关世界书、当前 MVU、同一张人物骰票、既有档案和医生世界状态主动设计完整档案。
- 人物阶段只使用一份完整字段合同，明确身份、外观、生理、十四轴人格、经历、当前状态、关系、知识、能力、资源、证据和可修订推断；禁止用“未知、待定、未登记、正文未提及”逃避补全。
- 修复次数现在表示首次生成后的额外重试次数；每轮都保留最佳候选并优先解决精确缺项，手动重试也从保存的候选继续，不再重新生成整批人物。
- 修正“男、女、人”等合法单字被误判为空字段的问题；“无、不详、未知”等占位值仍会被拒绝并要求自然补全。
- 角色卡和世界书中的权威人格可以覆盖冲突骰轴；人物骰票只为真正空缺的轴提供首次出场默认值。旧人物的局部更新会自动继承已持久化的完整档案后再原子提交。

## 0.3.1 人物档案根因修复

- 严格 JSON 先原样解析；只有确实解析失败才进入宽容修复，合法字符串里的中文引号不会再被修复器反向破坏。
- 宽容修复改为字符串边界感知，只处理字符串外部的注释、裸键、单引号结构、缺逗号和尾逗号。
- 每次人物修复保留并合并上一轮最佳候选，只把缺失字段和错误类型交给下一次修复，不再整张推倒重做。
- 可确定的列表类型由代码归一化；正文证据只从最终叙事区提取，不把思考链、变量块或未执行选项冒充已经发生的事实。
- 医生耗时从 `accepted-final` 开始计算；完整报告另存总生成链耗时，正文生成等待不再算进医生耗时。

## 0.3.0 前端与基础功能

本版前端从零编写，没有复制旧医生的 HTML、CSS、组件或任务控制结构。旧版资料只用于确认用户需要哪些入口。

- 总览：本轮阶段、普通中文状态、档案/世界项数量、票据数、召回上限、修复次数、取消与失败步骤重试。
- 连接：继承酒馆当前模型或使用独立 OpenAI-compatible API；支持地址、可选密钥、模型、模型列表获取、真实响应测试、人物/世界输出上限，以及唯一的全局模型适配附加提示词入口。
- 人物：按姓名选择并查看身份、外观、生理、十四轴人格、经历、当前状态、关系、知识、能力、资源、正文证据与可修订推断。
- 世界：查看世界摘要、支线、NPC 行动倾向、约定与敌对计划；NPC intent 始终标为倾向/尝试，不冒充世界裁决成功。
- 诊断：保存当前聊天最近 30 条脱敏记录与最近 6 次完整运行记录，显示失败影响和“怎么解决”，支持复制脱敏诊断、清空诊断、安全重试同一最终正文的失败步骤，以及“导出完整报告（除API）”。完整报告含私人正文，不能公开上传。
- 移动端：窄屏使用全屏控制台，桌面使用右侧大面板；所有正文、人物与世界数据都以 `textContent` 渲染，不把模型内容作为 HTML 执行。

自定义 API 密钥保存在 SillyTavern 的医生扩展设置中，不写入聊天 metadata、诊断记录或仓库。若所用端点不允许 WebView 直连，可改用“继承酒馆当前模型”；本候选尚未实现旧医生的后端代理、多连接预设和多槽位路由。

## 明确边界

- 数据库：扩展不读取、不写入、不声称代表数据库成功。
- 预设：不上传到本仓库；本地适配版以用户优化最新版为唯一母版，保留原 242 个 prompt、209 个顺序项、原有参数和正则，只把重复启用的人物适配补丁收束为一个统一入口。
- 医生：正文后依次处理 MVU 变量检查/修复、人物档案和世界连续性；人物首次出场的人格随机仍由生成前脚本票据决定。
- 世界引擎：记录 NPC 的计划或尝试，不把未裁决尝试伪造成成功结果。
- 玩家自主权：脚本和追加提示均禁止替玩家决定行动、感受、同意、关系或结果。
